## ADR42 - Explicit retirement of an unresolved nonfinancial operation

Under the owner's ongoing implementation/efficiency request, close the finite lost-draft recovery dependency described in USABLE_RELEASE_MILESTONES.md. An absent lookup alone cannot safely release an uncertain original: an earlier transaction may still commit. Select a distinct immutable audited operation.retire decision competing on the existing unique business/operation key. Reject a UI-only storage clear or second independent decision table: neither supplies the original writer's serialization fence. Keep the existing architecture, typed commands, source/audit history and financial semantics. This adds no finance cancellation, undo, reconstructed lost draft or automatic replacement/retry.

Scope exactly the eleven implemented nonfinancial originals: business rename; customer, address and vehicle saves; vehicle association open/close/transfer; lead source, lead and lead-state changes; lead-owned vehicle/address saves; atomic lead conversion. Strict versioned original references retain original IDs, parent/action IDs, decimal versions and original recovery epoch without drafts, credentials or caller-selected actors. A retirement carries a separate current recovery epoch and an explicit1..2000 Unicode-character owner reason. Normalize accepted numeric schemaVersion1 before canonical hashing; never normalize IDs, versions, reason or original epoch.

Reuse the closed crest_command_owner and crest_session_owner, existing operation/audit tables and deferred committed-evidence checks; no new role/table or browser table authority. Add only narrow retirement RLS policies, listed audit reason/read columns and fixed helper/web execution grants. Recheck genuine current provider-backed recent authentication, active owner membership and enabled current recovery authority under the ordinary mutation locks before claim and after waits. Knowledge of a UUID supplies no authority. Another actor's existing claim stays hidden/conflicting; employee capability alone cannot retire it. Source/audit/decision commit atomically and remain immutable.

If the genuine original commits first, preserve it unchanged and return only original_recorded: the existing typed original lookup must independently verify its receipt before releasing the pending reference. If retirement commits first, every late original writer must conflict before domain effects. A rollback leaves the competing claim eligible; all original/retirement win/rollback orderings must be proved on real separate connections, including conversion parent and derived-child full rollback. Reads may inspect a historical decision while writes are paused, with fresh recent owner authorization; they do not rebase the original or historical retirement epoch. An absent result is still only an observation. A changed review cannot replace the retained decision.

Private runtime composition must explicitly opt in after registered schema/restore/consumer acceptance. Fixed POST retirement and resolution paths pin the configured business, trusted origin, current CSRF and ordinary durable admission, bounded fatal UTF-8/duplicate-free typed bodies and private/no-store results. Clients bind exact original/review evidence, retain ambiguous sent outcomes, perform no automatic lookup/retry and generate no replacement identity. Owner controls must explicitly review/confirm retirement or reconcile the original receipt; only complete bound durable evidence permits exact-reference removal with acknowledged storage clearing. A storage mismatch/failure stays visibly blocked. Hiding/closing clears private review fields and credentials, retains original metadata and ignores late responses. Later work is a newly reviewed draft after the original is demonstrably fenced, never replay of a lost draft or a financial correction.

Use the complete existing16-column operation and20-column audit source projections, retaining original JSON-text precision, bigint strings, audit/hash bytes and UTC microseconds. Reversible RFC4180 CSV/null/backslash/formula maps and dictionaries carry exact part hashes and honest incomplete-export/backup flags; the16MiB CSV processing bound never truncates source. Require registered forward42 with every prior SQL byte unchanged, ordinary mandatory native tests, and an independently keyed encrypted registered restore after loss of the original key. Restored fresh authority must read the exact retained decision, keep stale mutation epochs closed and reject late originals. Source consistency alone does not prove authentic capture, custody, complete portability or recoverability.

Status: selected technical design; isolated core/source proof exists, implementation/release/production acceptance remains gated. See planning/PHASE_4_ORIGINAL_OPERATION_RESOLUTION.md. Preserve Calendar scope, all accounting/security/privacy/recovery/real-data gates, default closed activation and $0/no provisioning. This ADR does not authorize paid services, production grants/apply/deployment or real records.

## ADR36 - Exact-target provider-session reduction in the database

2026-10-23. Selected implementation design within the existing Phase2 session-recovery/revocation scope, following the owner's continuation. Synthetic implementation/testing is authorized; this is not permission for a hosted grant, maintenance login, production migration or activation. Retain Supabase Auth, password/TOTP verification, the standard Node application and all security/recovery gates. This explicitly extends the maintenance trust boundary; ordinary web/worker/recovery/inventory callers gain no provider-write authority.

Choose one fixed PostgreSQL definer operation, called by a separate nonlogin/noninheriting maintenance role, for the exact provider target derived from a schema23 cleanup request. Freshly validate its stopped finish, original signed target, immutable actor/epoch/source hashes and any revoked registration/reference under the schema22 producer lock. Provider deletion and immutable outcome capture share one transaction. Input is request ID plus expected actor/configured issuer, never an arbitrary provider UUID, token or broad user scope. Duplicate execution replays original evidence without repeating deletion. Outcome append failure/rollback restores provider rows and pinned cascades together. Bound provider-row waits and deny source conflicts.

The pinned Auth v2.197.0 implementation of local logout uses deletion of one session, with refresh-token and MFA-AMR child cascades. This adapter performs that narrow row reduction with an exact subject predicate; it does not emulate an HTTP logout response or insert a fabricated provider audit entry. Crest records its own immutable maintenance outcome. At migration and new execution, reject an unsupported provider migration watermark, ownership/RLS/table/key shape, changed/extra cascade dependencies, rules or user triggers. The isolated definer receives session ID/user-ID SELECT, session DELETE and the provider migration-version projection, plus safe Crest evidence reads/append. PostgreSQL17 MAINTAIN on only the two pinned child tables permits ROW EXCLUSIVE locks on all three provider tables before inspection through commit, fencing trigger/FK/schema DDL while allowing ordinary provider writers. This is the narrow available lock privilege without child secret SELECT or child INSERT/UPDATE/DELETE; its additional physical-maintenance capabilities remain confined to the fixed nonlogin definer and are not exposed through an API. No provider secret, user/factor write, UPDATE or application-role grant. The definer/caller are not service logins; provisioning remains a separate production gate requiring actual operator permission/support. An unsupported managed-provider permission/schema profile stays blocked and requires a reviewed supported alternative, not privilege bypass.

Alternatives: token escrow violates local revocation erasure; retrying an expired/missing token cannot prove cleanup; broad user logout harms other devices; forging tokens or retaining an administrative JWT is excluded. The official token-authenticated logout API remains the existing best-effort immediate path. A durable token-free database adapter is selected for this narrowly proven maintenance case, not a provider/runtime switch. Check current provider support/privileges before deployment; the pinned adapter must be reviewed/retested on every provider schema upgrade.

provider_removed records the exact transactional row removal. provider_absent_observed records a distinct point-in-time absence. Neither means all external I/O ended, all orphan sessions are gone or a still-unexpired signed JWT became cryptographically invalid. Crest's fresh provider/local checks remain mandatory; historical replay/lookup grants no fresh action or eligibility. Broader unknown/unfenced/legacy/enrollment cases, leases, bounded dispatch/telemetry, recovery/export and production grants remain gates. No scheduler/route/runtime adapter is activated.
