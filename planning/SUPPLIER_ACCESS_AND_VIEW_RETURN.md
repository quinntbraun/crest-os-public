# Supplier access and expense-view returns

The remaining S06/S13 review found that SupplierBillDrafts.run displayed a generic failed-read message after a real denied session but retained the loaded supplier list, selected bill and editor. Expenses also kept Purchases/Suppliers/Exports only in local state, so a fresh sign-in could reopen the wrong view.

The supplier task now distinguishes AuthenticationError('denied') from an ordinary connection failure. It clears the task's private form/list/selection/evidence state, focuses an explicit notice and offers sign-in. A directory read is blocked while a save is pending and creates no original reference, so only that safe branch also invokes the existing parent access-denied callback and clears the entire expense workspace. A denied write/lookup keeps its existing pending reference and payload in this tab, hides the editable workbench and offers explicit original lookup. Its sign-in link opens a new tab to preserve the existing in-memory recovery record; the screen tells the user to return and check it. An authorized parsed lookup or directory read restores the ordinary task. No request automatically retries, changes its original identity/epoch, or posts accounting entries. This does not add cross-tab or durable storage for supplier draft payloads.

Expense view navigation uses a finite view hint. The existing Purchases default stays /expenses; Suppliers and Exports use ?view=suppliers or ?view=exports. User tab changes replace this navigation hint without fetching or saving a record. The server page validates the hint before passing an initial view to ExpensesScreen, and sign-in return parsing accepts only those two nondefault values. Unknown/array/URL/private values do not become a destination or authorization. Private expense data is cleared on suspension/denial; the harmless view choice remains. A supplier view without the current supplier capability falls back to Purchases. No unsupported financial capability is enabled by the hint.
