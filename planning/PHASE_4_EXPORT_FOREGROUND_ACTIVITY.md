## Consistent lock ordering

The earlier private download gate called the read authorizer first, which held recovery-root/session SHARE locks, then upgraded the session through the mutation fence. Two simultaneous requests for the same session could deadlock while upgrading. A new closed helper now locks actor, business and session FOR UPDATE before calling the read gate and its recovery fence. This agrees with existing mutation/session refresh/revocation ordering. Metadata SQL ends before object-store/network I/O; the lock is not held across a file transfer and does not refresh inactivity by itself.
