## Original command and receipt boundary

`src/security/source-export-job-contract.ts` defines the data-only shared boundary for request, claim, expire and stop. Each command retains its complete original business, operation, recovery epoch and job IDs plus the frozen release/profile/schema for requests or expected version and lease for transitions. These are small non-PII references; a future pending store must preserve them exactly across interrupted requests and deployments. Never replace an uncertain original command with the current release/epoch or new IDs. No pending store, transport, owner screen or dispatch is implemented here.

Every immutable receipt contains exactly schemaVersion, command, job and auditEventId. The database independently reconstructs the retained command from its immutable operation and audited before/after projection. In particular expiry retains the original lease in command even though the resulting job clears its lease. The shared parser binds the receipt to that exact original command and authenticated recording actor, validates all22 projected columns, preserves bigint versions and UTC microseconds, and checks the allowed resulting state. An explicit current-owner stop may retain an older job epoch or creator; its operation epoch and recording actor still match the original stop command. A historical Running receipt proves no current lease, session or download authority.

Sixty-six focused unit cases cover closed shapes, copied/frozen values, original-reference and actor mismatches, exact version advancement, expiry lease binding, historical stop provenance and invalid source state/timestamps. Each committed result in the native command wrappers now passes this independent parser, and all five expiry cases reject a different original lease after an actual database lookup. Genuine database execution must still accept the corrected source.

## Durable snapshot plan continuation

Apply the unregistered `proposals/source-export-snapshots.sql` only after the request/lease proposal in the same disposable forward43 transaction. It adds forced-RLS append-only `crest_private.export_job_snapshots` and two fixed commands: authorize_source_export_worker and record_source_export_snapshot. They reuse the existing closed command/session owners. Every invocation, including an exact replay, requires fresh provider/session/recent-owner/export.bulk/recovery checks, the original actor/epoch and a currently Running unexpired lease; lock the job and recheck after waiting. A final authorization/expiry check precedes a snapshot acknowledgment. No external I/O occurs under the database lock. No raw table/helper access is granted to web callers.

One snapshot per job/lease freezes its generation, observation instant, release/schema, ordered file inventory, original request text and request/plan hashes. The source observation must be a valid UTC instant no earlier than that lease's server-stamped beginning and no later than database time. Retain exact original UTF8 request bytes. Compute the plan hash from the original JSON plan substring, rather than PostgreSQL's reformatted jsonb. The command acknowledgment hashes the complete original request; a byte-identical replay is allowed only while live authority remains valid. A changed generation, inventory or root whitespace cannot replace a recorded plan. Stop/expiry preserve this fact; a future attempt must capture a new generation under a new lease.

Reject duplicate keys before jsonb conversion using PostgreSQL17 [IS JSON OBJECT WITH UNIQUE KEYS](https://www.postgresql.org/docs/17/functions-json.html#FUNCTIONS-SQLJSON-IS-JSON), including duplicates in nested objects. Require closed request/plan/claim/file shapes; pinned schema43/release/business/actor/epoch/lease; false full-reference/export/backup flags; unique part IDs and safe unique filenames with exact MIME; sorted ordinary names with the separate source manifest last and its exact hash. Bounds are1MiB request,2–1024 files,8MiB per file and64MiB total. No plaintext source data, encrypted bytes, credentials or arbitrary filters enter this metadata journal. A snapshot records the declared inventory, not independent proof of source capture, uploaded bytes, verified custody or Ready status.

Snapshots reference their retained claim attempt/operation, freeze creator/origin and receive a database insertion timestamp. Private INSERT guards independently validate the complete original request and its projected metadata; table constraints bind original bytes to their hash. Update/delete/truncate are refused. No new generic operation/audit entry is appended for routine progress, avoiding per-file duplication of the general history; the lease's immutable audited claim anchors this append-only fact.
