## Original command and receipt boundary

`src/security/source-export-job-contract.ts` defines the data-only shared boundary for request, claim, expire and stop. Each command retains its complete original business, operation, recovery epoch and job IDs plus the frozen release/profile/schema for requests or expected version and lease for transitions. These are small non-PII references; a future pending store must preserve them exactly across interrupted requests and deployments. Never replace an uncertain original command with the current release/epoch or new IDs. No pending store, transport, owner screen or dispatch is implemented here.

Every immutable receipt contains exactly schemaVersion, command, job and auditEventId. The database independently reconstructs the retained command from its immutable operation and audited before/after projection. In particular expiry retains the original lease in command even though the resulting job clears its lease. The shared parser binds the receipt to that exact original command and authenticated recording actor, validates all22 projected columns, preserves bigint versions and UTC microseconds, and checks the allowed resulting state. An explicit current-owner stop may retain an older job epoch or creator; its operation epoch and recording actor still match the original stop command. A historical Running receipt proves no current lease, session or download authority.

Sixty-six focused unit cases cover closed shapes, copied/frozen values, original-reference and actor mismatches, exact version advancement, expiry lease binding, historical stop provenance and invalid source state/timestamps. Each committed result in the native command wrappers now passes this independent parser, and all five expiry cases reject a different original lease after an actual database lookup. Genuine database execution must still accept the corrected source.
