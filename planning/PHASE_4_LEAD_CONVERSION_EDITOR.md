# Explicit private lead conversion editor

The owner explicitly chooses a new or current existing customer, then selects reported vehicles and locations and chooses each destination. Nothing is selected from matching contact text. A previously linked lead requires that same existing customer. Existing vehicle records remain unchanged; existing addresses must belong to the selected existing customer. New customer contacts/notes start unknown and separate from the retained inquiry. The form never truncates inquiry evidence into a smaller customer notes field. New vehicles require an explicit classification choice and establish no ownership; new locations retain incomplete/raw location and exact decimal/microsecond evidence. No geocoder, inferred verification, work acceptance, Won transition, job or financial entry is involved.

Source and destination pages are bounded and manual. Earlier source selections remain in memory across pages with their original IDs and versions. Every manual source or original-mapping page obtains a fresh session proof and business context: destination searches rotate request proofs, and the unchanged session store retains only eight. Source paging requires the original sign-in binding, recovery epoch and write state; a changed context clears preparation instead of rebasing it. Every selected source needs a destination. Zero optional resources is a valid explicit customer-only conversion. Draft edits invalidate the complete review; target identities remain stable until deliberately replaced. Complete preparation uses the shared contract/preview and bounded wire serializer, rejects oversize selections as a whole, and never silently drops evidence. The final screen displays source and target fields/versions and requires an explicit acknowledgment before its one atomic command.

Only a small exact-schema per-tab original reference is persisted: business, opaque sign-in binding, operation, recovery epoch, conversion, source lead/version and customer IDs. No customer names, contacts, notes, coordinates, selections or credentials enter storage. The controller rechecks business, sign-in, recovery, sibling references, storage write/read-back and exact reference identity immediately before dispatch. Default conversion activation stays independently closed in the server composition.

Unknown responses retain the original reference. Checking uses only that original operation and never submits a mutation. An absent lookup does not prove a prior request failed; explicit unchanged retry additionally requires the original complete in-memory draft, same binding/epoch/source and no sibling pending change. Reload, hiding or disposal destroys that draft and cannot authorize a replacement. A committed receipt clears only the exact original reference, after acknowledged storage removal. Definite input/unsubmitted/denied first attempts and rolled-back domain conflicts can clear their own reference; operation conflicts and failed storage remain blocked. Four sibling controllers independently refuse mutations when conversion reference storage is pending or unreadable. The screen propagates in-memory draft locks and refreshes sibling source versions only after confirmed conversion.

Hidden-page, pagehide and restored-page handlers abort pending reads, clear private fields/search/results/reviews and ignore late responses. A reference survives for manual review. Recorded conversions expose read-only original metadata and manual mapping pages. React text escaping applies to raw evidence. Controls use explicit labels, semantic sections, keyboard focus/status messages and mobile fieldsets; browser accessibility checks are part of acceptance.
