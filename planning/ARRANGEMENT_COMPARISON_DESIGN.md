# Saved and proposed service availability

November18 follow-through for R17 in the November17 end-to-end design audit.

Mobile detailing, Drop-off and Pickup and return now each have a consistent comparison row: mode context, actual saved state, proposed native selector and a change/unchanged note. Desktop aligns these in three columns; phone/tablet stacks labeled facts and controls. The saved state is read from the validated retained version, or explicitly from the approved initial defaults before the first version. A proposed value never replaces the displayed saved value.

One named Availability for new bookings section contains the version/time context and editor. The recorded instant uses the workspace time zone. The shared explanation explicitly limits changes to future booking checks and states that existing booked jobs keep their recorded service arrangement. Mode explanations describe service location, separately reviewed custody arrangements, and separate transport/operating approval. These explanations are not computed booking-eligibility results or claims that a policy is approved. The native selector's accessible description identifies the proposed state before its context/change note; comparison sections have distinct names from controls.

Initial defaults remain readonly until recorded through the existing command. Reason, all-disabled warning, write gates, original request retention/check/retry, privacy suspension and append-only version history remain unchanged. Older-version Availability facts and retained ZIP/CSV/checksum evidence remain. The redundant separate current-state card is removed; no extra policy editor, business rule or database change is introduced.
