## Decision and boundary

Schema23 adds provider_cleanup_requests. The existing isolated crest_inventory caller receives three fixed functions to request, read and page requests; crest_inventory_owner gets SELECT/INSERT only on the new forced-RLS table. No new role, membership, login, upstream/source privilege or provider write is added. The source must be an exact schema22 stopped_review finish and a schema21 signed target from the same original attempt/actor/epoch/issuer/subject. A stop with an unknown target is rejected; later original signed evidence can support a new explicit request without rewriting the stop. AAL1 evidence, a start, registration_closed, an inventory label, age or an arbitrary provider UUID cannot substitute for that source. Caller inputs contain only request UUID, finish UUID, expected actor and configured issuer; provider session, subject, epoch and source relationships are derived.

If the reserved app row exists, it must match the exact target, actor, original epoch and unique original CREATED event for that attempt; it must already be revoked and have its existing schema17 reference. A different app bound to that provider UUID, a live registration or a conflicting source rejects selection without changing any source. Original actor binding is immutable; disabled/old-epoch history remains usable for reduction review, never access. Provider absence/expiry is not queried or inferred. Even a stopped local producer does not prove all external I/O has completed, and privileged historical/direct paths remain outside ordinary fenced issuance. A future executor must revalidate source/current provider/environment under its reviewed synchronization contract immediately before any action.

Selection and execution are deliberately distinct. state is permanently pending_review. A request is not a provider capability, executable lease, completed cleanup, provider-absence finding, user/device eligibility or proof of cookie/browser delivery. A separate reviewed executor/evidence ledger is still required. Broader unknown/in-flight reconciliation cannot automatically close on a timeout. This bounded first source excludes ordinary logout-only/legacy/enrollment cases lacking a stopped finish/target; no historical evidence is invented and no generic UUID revocation API is introduced.

## Retention, replay and grants

The invoker INSERT guard validates the source and shares schema22's nonwaiting lifecycle advisory lock. A request-scoped domain-separated nonwaiting lock makes same-ID overlap busy. Exact committed replay returns original UTF8 JSON/SHA256 without rescanning provider or source state; different finish/actor/issuer conflicts. Another request ID cannot adopt a previously selected source/target. Source uniqueness plus the lifecycle lock protects different-ID concurrency; rollback/append failure leaves no partial request and changes no source. Historical lookup is exact actor/issuer and can run read-only; absent lookup is not proof an in-flight transaction cannot still commit. Bounded1..100 UUID-keyset pages are historical and not a complete cross-page snapshot; inserts behind a cursor require a fresh sweep.

All body/provenance/state/hash fields are server-derived, including supplied forged direct-insert fields. Source finish and target hashes preserve portable ancestry alongside source IDs. No JWT, refresh token, credential digest, ciphertext, key, password, code, email or raw provider diagnostic is retained. Hashes provide independent byte verification, not signatures or tamper-proof attestation. Ordinary privileged UPDATE/DELETE/TRUNCATE are rejected. A later authorized security recovery/export package must preserve these original rows/bytes and referenced history; customer exports gain no global security access. There is no purge.

The migration reviews existing definer roles (including the isolated caller), memberships, CREATE/default privileges, forbidden safe-reader source writes/secret reads and upstream fixed-routine metadata before applying. No existing migration is edited. Fixed search_path/row_security, forced RLS, invoker UTC/ISO derivation, PUBLIC revocation and removal of temporary ownership-transfer CREATE grants remain. Ordinary web, worker, recovery, provider and session roles cannot request/read/list this metadata. No runtime adapter, scheduler, endpoint, UI or production account is provisioned.
