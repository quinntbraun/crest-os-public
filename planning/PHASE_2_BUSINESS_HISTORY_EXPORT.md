## Contract and boundary

ADR38 extends ADR37's isolated nonlogin export definer with explicit safe SELECT for36 current columns across operations and audit_events, under new SELECT-only policies and unchanged forced RLS. Migration29 reviews closed role attributes/memberships/defaults, source ownership/RLS, existing configuration routines and unexpected source/provider/sequence privileges before adding access. No new role/login, ordinary runtime grant, source write or provider/actor/session read. Schema28's source readers remain unchanged. The trusted isolated caller is privileged across businesses; one business UUID scopes each extraction, not protection against a compromised privileged credential.

business_history_export_context(business_uuid) validates the existing business configuration roots and captures all operation/audit counts, business_history schema1, observation time and a domain-separated snapshot/scope fingerprint. An existing business with no history produces explicit zero counts. It does not filter through active membership/actor, current security or recovery epochs, business status or writes-enabled state. Actor/creator IDs remain unresolved references; no global actor/profile/history joins or cross-business membership inference.

business_history_export_page(business_uuid, token, kind, after_uuid, size) reads operation or audit_event only, with fixed business predicates, ascending UUID keyset pages1..20 and one caller-owned READ ONLY REPEATABLE READ transaction. Configuration/history scopes use different fingerprint domains. Repeated context observation times can differ even when counts/fingerprint remain stable. These unkeyed fingerprints are not generation IDs, database identity, authorization or snapshot authenticity.

Every returned envelope is snapshot_projection with a newly computed body SHA256. Its schema1 body includes kind, businessId, jsonTextColumns and an explicit row object containing every current source column. jsonTextColumns is exactly [result] for operations and [delta,payload] for audits. Those JSONB columns travel as their exact PostgreSQL JSONB text strings, retaining unsafe numeric lexemes without JavaScript Number parsing. Consumers use the declared dictionary and types to decode/reimport, never infer encoding from string appearance. Null remains null; audit entity_version is decimal text; row timestamps retain microseconds in UTC. Original audit hash_input is already a text column, not relabelled or rewritten.

Validate original audit payload equality to hash_input::jsonb and its exact hash_input bytes/hash, plus every source-column binding defined by the original schema13 audit capture (including IDs, actor/operator, entity/version, delta, principal, provenance and exact event/effective times). Keep original hash_input/event_hash unchanged inside the row, distinct from the new wrapper hash. Each audit must link to a committed matching operation/actor/provenance; each operation must be committed with a valid versioned receipt and a matching audit. Corrupted or incomplete source rows fail, not disappear behind an inner join/state/eligibility filter. Counts alone make no consistency claim. Self-consistently forged source history under privileged compromise can still pass; no authenticity/incident-clearance/restore authority is inferred.

## Bounds and failure behavior

Operation receipt source <=64KiB, source audit delta <=256KiB and original hash_input <=512KiB; explicit projected body caps256KiB/2MiB respectively accommodate current valid source rows and escaped nested text. Each page has an aggregate8MiB body limit. Validate bounds/source evidence before emitting rows; no truncation, filtered damaged rows or partial-page success. An error aborts the transaction. Roll back and discard incomplete output; a fresh explicit generation can choose smaller pages. No automatic retry, rebase or cross-snapshot combination.

Whole-job memory/time/generation/shared-lease limits and encrypted streaming parts are still worker-composition requirements. There is no new collector, request/queue, filesystem/network publication, manifest/Ready, download, HTTP/CLI/scheduler, restore writer or default-runtime activation. Reading hashes/metadata does not authorize cleanup, business writes or restoring historical epochs/session authority.
