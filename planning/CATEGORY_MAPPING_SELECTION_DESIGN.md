# One category directory and effective-date review

November18 follow-through for R30 in the November17 end-to-end design audit.

The category route now has one searchable category directory and one shared effective-date toolbar. Selecting a row opens its named detail, dated account lookup and retained approval history. The duplicate category select is removed. Desktop keeps the directory beside the selected detail; phone/tablet shows the selected category above its lookup/results and provides Back to categories. Search, filter, effective date and the loaded directory remain mounted on local Back. Selection receives committed-DOM heading focus; Back restores search focus. Selection/back/search do not make business requests.

Category definitions are explicitly distinct from posting treatment. Unchecked entries say Posting account not checked. Only actual verified per-date reads show an approved account; an absent usable mapping remains explicit. Changing the date clears old lookup/directory results and filters that depend on those results. A category still being listed does not imply accounting readiness. Existing effective/exclusive dates, approval/closure history, immutable reasons, original-save recovery, eligible-account gates and CSV remain intact.

Fixed-purpose mappings keep their existing selector and side-by-side lookup/history composition. Both routes share the original authorized read functions, bounded batch verification, historical pagination and privacy clearing. Hiding/suspending the private workspace still clears selection, query, dates and loaded private results; local Back preservation is not reload/offline persistence.
