# Accounting report choices and date return

The report library previously kept its selection and all date filters inside mounted report components. Changing reports discarded dates; clearing the private accounting workspace or reloading also discarded selection. The section alone was preserved by sign-in navigation.

The accounting workspace now owns harmless report navigation: the selected section, one of the four existing reports, and separate validated dates for each report. The URL and accounting sign-in return carry only that finite metadata. Invalid, duplicated and impossible dates are dropped. Names, balances, financial drafts, original posting references and authorization are excluded. Other destinations do not inherit these filters.

Reports still clear snapshots, journal rows, downloads and private account selections on hide, access loss or unmount. A definite denied read from any report now invokes the accounting parent's existing private-clear path, removing even the hidden account/setup workspace and focusing the sign-in notice. Ordinary connection failures retain their retry messages. Remembering dates never triggers a report request. A returned report requires the existing explicit Load action and fresh server authorization. Accounting permissions, financial calculations, posting commands, exports, schema and migrations are unchanged.

The original paid-expense financial browser journeys retain all existing posting, original-request, ledger, journal and CSV assertions. The income variant adds report-switch date retention, pagehide/private clearing, explicit access recheck, reload, actual signed-out return-link metadata and mobile/desktop layout checks. It explicitly observes that restoring filters sends no report request. Rendered proof and release acceptance must be recorded against their actual source; writing the assertions is not a passing run. Customer-funds and receivables date wiring additionally require their configured browser coverage before broader acceptance.

This is additional implementation for original S13 and S06. Neither group nor the original audit is fully signed off by this change.
