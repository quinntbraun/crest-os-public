# Database and retained-object recovery

2026-10-24. Continue ROADMAP Phase3 and EXPORTS_AND_BACKUPS5/7 from PR65/main393206cce63e83fcf0c1951b15f31c6951d1bc96. No canonical amendment, migration, production access or service setup.

`src/tooling/object-recovery.ts` is isolated recovery-tool orchestration. It accepts an exact retained inventory from the held DB snapshot, read-only source access, standard age encryption and append-only vault/verification capabilities. The backup side gets no decryption identity. It checks original length/SHA-256, encrypts each object, creates point-scoped ciphertext and independently reads/checks it. Only after every entry succeeds does it encrypt, create and verify the manifest. The receipt and expected inventory are bound into the encrypted DB manifest. `completeBackup:false` is explicit: this object archive is not the complete backup service.

Inventory must include retained Archived originals, derivatives and quarantine, with no Available-only filter. Known retained quarantine requires an exact digest; staging replacement fails that digest. Pending uploads without verified bytes remain incomplete metadata. No decoder, listing, deletion, overwrite, retry or public retrieval is added. Original keys/hashes/classifications are encrypted; vault names use an opaque point/index.

Restore checks the receipt, point and every entry against the independently trusted decrypted DB manifest. It authenticates every object before any destination write, rechecks during copying, creates without overwrite and independently verifies destination bytes. Missing, corrupt, omitted, substituted or undecryptable objects withhold success. The combined drill checks/restores objects before SQL; a missing original cannot silently yield database-only success. Late failures can leave private candidates: retain and reconcile, never automatically delete/retry.

Callers must durably reserve point/destination identities before dispatch and reconcile unknown outcomes. This module adds no lease, scheduler or incident authority. Five-minute invocation signals must be honored by adapters, which also enforce streaming read bounds. Inputs are copied before awaits. Bounds:1000 entries,256MiB aggregate plaintext,25MiB/object,8MiB/preview,2MiB manifest,64KiB age overhead. Serial one-object processing; overflow fails explicitly. These are bounded implementation limits, not F8 capacity/RPO/RTO proof.

`tests/support/object-recovery-drill.mjs` supplies bounded private disk transports, hashed filenames,0600 exclusive creates/fsync and pinned real age1.3.2. `test:object-recovery` covers exact round trips, fresh-process emergency-copy recovery after original key/source removal, missing/corrupt/truncated objects, authenticated tampering despite recomputed hashes, wrong/missing keys, inventory substitution/omission, unsafe keys/bounds, vault/destination readback, overwrite refusal, unknown writes/no retry, late vault mutation, input mutation and cancellation. Rejected synthetic bytes are copied without rendering.

The real PostgreSQL17 drill captures an explicitly drill-only object inventory in the same exported snapshot as dump/row fingerprints. A fresh process restores files and DB in a separate cluster. Archived/quarantined files are included; a concurrently committed object is absent from both restored rows and files. Missing originals fail before SQL/destination publication. An object archive requires explicit restore transport. No fake application parent/domain table or runtime grant is introduced.
