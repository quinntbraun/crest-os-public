# Isolated HEIC original validation and previews

2026-10-24. Implementation under existing SECURITY5/TESTING F6/P09. No schema, canonical rule, provider setup, spending or real-data approval changes. Candidate/actual-main proof must be recorded in the PR before calling implementation verified.

## Bounded decoder decision

Build official SHA-256-pinned libheif1.23.6 and libde2651.1.3 from source. The npm libheif-js1.23.5 wrapper was considered but is behind the upstream security release. Native decoder support and npm audit are distinct checks. Enable only the libde265 HEVC decoder; disable plugin loading, other codecs, encoders, uncompressed formats and parallel tile decoding in the release. A thin C++ adapter uses strict decoding, no broken-input autocorrection, one codec thread, a60MP pixel cap, bounded item/tile/profile/allocation limits and rejects all reported warnings. It fully decodes the sole top-level static image including geometry/alpha before preview processing. Multiple independent images, sequences/video, AVIF and unsupported formats quarantine. Static HEVC content may use image/heic or image/heif MIME; detected type is image/heic.

The initial candidate failed compilation because its sequence-check call uses an API outside the default stable umbrella header. Keep the default stable still-image API: the Node framing gate rejects sequence brands and movie/video boxes before invoking native decoding, and the native adapter enforces one top-level image. No experimental API, failed release gate or unsupported format is enabled to work around that failure. The native adapter now compiles/checks before building the separate test encoder.

Both LGPL libraries remain dynamically replaceable. Their exact source archives, notices, supplied adapter/build recipe, compiler/package receipt and rebuild instructions travel in the runtime image. libpng's static-link notice is retained; zlib/C/C++ use the existing base-image runtime. The installer builds a separate x265-enabled encoder only with --fixtures for synthetic CI inputs; that GPL test encoder/prefix is never copied into the release. No app-wide licensing change is made. Recipients retain the library replacement/debug/relinking rights required by LGPL; no signature/key prevents rebuilding the supplied adapter.

## Original, color and preview contract

Seal1 byte through25 MiB and independently hash unchanged original bytes. Walk top-level ISO BMFF boxes with bounded sizes/count, strict ftyp/meta/mdat framing and static HEVC brands; native inspection is still required after framing. Reject truncation/trailing payload, unsafe extents, wrong MIME, unsupported format and decode/limit failures with stable redacted codes.

The adapter checks signalled and actual decoded plane dimensions/bit depth/stride before consuming every pixel. It applies HEIF cropping/rotation/mirroring during decode and writes a private bounded PNG intermediate, never a replacement original. Source ICC profiles are retained only in that intermediate for Sharp's color conversion; without ICC, libheif requests sRGB output. HDR is reduced to8-bit SDR for the JPEG preview while the original HDR file remains unchanged evidence. Preview generation resizes inside2048 pixels without enlargement, composites alpha on white and emits JPEG quality85 with metadata stripped, capped at8 MiB. Record original SHA-256/size/type/encoded and display dimensions/bit depth plus independent preview digest/size/dimensions. Capture timestamps/EXIF remain untrusted private original evidence.

## Isolation and gates

One same-release server/heic-worker.mjs invocation reads original stdin and returns private JSON/base64 preview stdout. No credentials, filename, provider URL or database handle is accepted. Admission reuses Linux/non-root/read-only/no-capability/NoNewPrivs/seccomp/no-network/cgroup-v2 checks. Its fixed memory ceiling is1 GiB with zero swap; JPEG/PNG/PDF keep their existing512 MiB ceilings. Full HEVC image planes and a private PNG intermediate justify testing this separate bounded profile instead of silently reducing the60MP original limit. This is a worker limit, not a paid host selection or provisioning decision.

Actual CI constructs network none, read-only/non-root, cap-drop ALL/no-new-privileges/default seccomp,1 GiB memory/no swap, one CPU,32 PIDs,128 MiB V8 heap and320 MiB noexec/nosuid/nodev tmpfs. Original plus bounded intermediate stay private and are removed after processing. Native subprocess receives a minimal environment without inherited credentials/loader overrides,25-second deadline and64 KiB output cap. Sharp preview processing has a10-second limit; the process watchdog is45 seconds. The external caller must enforce a60-second hard deadline,12 MiB stdout cap, terminate the entire owned container and discard stderr. CI records the exact owned ID before starting and removes that ID on every outcome. These are enforced-test profiles; production dispatch/orchestration is not configured by this slice.

Unit framing regressions run locally. Native and real restricted-container suites use the pinned actual decoder with generated8/10-bit, ICC/P3, alpha, rotated and tiled images, corrupt pixels/headers/containers, multiple images/video/AVIF, exact25 MiB/60MP boundary, metadata stripping, original/preview hashes, caller mutation, temporary cleanup, weakened isolation and stalled input. They remain mandatory alongside all previous gates. Windows has no local HEIC native toolchain/Docker proof; Linux CI must establish positive decode/build/container results. A library capability flag or AVIF decoder is not HEIC acceptance.

Actual synthetic iPhone camera/gallery files and real-device handoff still require F6/P18 proof before pilot. Generated HEIC files do not satisfy that gate. No Available attachment, authenticated upload/read route, typed parent/attempt/lease/recovery-epoch publication, actual storage conformance or full recovery claim is enabled. Those finite file/recovery dependencies remain ahead of the first usable customer/vehicle test build.
