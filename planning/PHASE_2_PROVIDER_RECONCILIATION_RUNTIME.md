## Bounded transport lifetime

A new regression failed against the prior shared maintenance adapter: finally cleared the overall timer then awaited pg.end(), allowing a peer that withholds shutdown to hold the completed call indefinitely. The private connection helper is shared by execution, original-outcome history and review, preserving their fixed role guards/SQL/contracts. It now owns a net.Socket through pg8.23.1's supported ClientConfig.stream factory, requests graceful end and destroys that owned raw transport on cancellation/error/deadline and all terminal exits. It never awaits peer shutdown or accesses pg private connection fields. pg's production TLS layer still wraps that socket with rejectUnauthorized:true; destroying the owned underlying socket also closes the wrapped transport. No dependency changed.

A completed non-pipelined pg query includes backend ReadyForQuery, so a successful schema24 autocommit result is already confirmed before terminal connection disposal. If the query fails or transport/cancellation intervenes before confirmation, the result remains review-required/unknown; no rollback, provider absence or execution retry is inferred. Inventory reads commit their explicit read-only transaction before publishing. Existing dispatch separately bounds uncooperative dependencies and stops after the first unknown.

Implementation references are the installed pinned pg8.23.1 client.end/connection stream factory/TLS handling, @types/pg8.23.1 ClientConfig.stream and Node24 net.Socket. These were inspected directly; no reliance on private pg fields or unpinned API assumptions.
