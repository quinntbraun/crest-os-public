## Bounds and assurance

Serialized input <=64MiB, <=1000 records, <=8MiB combined original projected-body bytes. Preserve schema29's256KiB operation/2MiB audit projection caps,64KiB receipt,256KiB delta and512KiB original payload/hash input caps. Nested source JSON processing has depth32,100000 nodes,10000 keys/object,10000 items/array and at most six exponent digits. These are explicit processing limits, not new source database constraints; a legal larger source must fail this bounded verifier and await a separately reviewed streaming path. No silent truncation, subset fallback, pagination retry or partial success. All failures expose only BUSINESS_HISTORY_EVIDENCE_REVIEW_REQUIRED with no source contents/cause.

Hashes, generation UUID, context snapshot fingerprint, principal and counts are unkeyed claims. A self-consistently forged collection or omission of an entire independent receipt+audit set can pass. Matching counts cannot prove live row completeness, source database identity, one actual snapshot, custody/authenticity, authorization or restoration. The routine performs no database/environment/network/filesystem/provider operation and is absent from runtime composition. No request/queue, collector/shared lease, encryption/Ready/manifest/download, HTTP/CLI/scheduler or restore writer is added.
