# Private instance-wide application source export

The existing179-table export is scoped to a business and its retained identity/
provider relationships. The ten operator-only runtime/global projections are a
different boundary. Concatenating those separately captured components cannot
establish a whole-instance snapshot or complete reference closure.

The new private instance source profile captures all189 reviewed application
tables and their required noncredential columns from one read-only repeatable-
read snapshot, using the existing strict dedicated backup-reader preflight and
coordination/migration lease. It includes every business and relevant global
record, not just the lease business. That ID coordinates capture and grants no
new ownership or browser authority. This is an isolated operator capability,
not a new product download. No migration, grant, role or financial rule changes.

The fixed inventory composes the existing business/identity/session/provider and
operator projections. A regression checks exact table/required/excluded sets
against SECURITY_EXPORT_COVERAGE138. Before any application-column cast, the
capture compares1269 routines and15454 structural observations against the
independent migration-only138 baselines. It also requires the exact189 table
names and every actual column to be accounted for by required/excluded fields.
Original canonical baselines are unchanged; none is learned from captured data.
This protects the known enum/domain/cast definitions without broadening the
smaller ten-source collector's built-in-type allowlist.

Capture reads fixed sources in primary-key order through bounded cursors. UTC,
ISO dates, PostgreSQL interval style, float text and hex bytea output are fixed.
Values stay PostgreSQL text, including exact cents/numerics, timestamps, JSON,
arrays, null/empty and references. The100000-row/64MiB capture and64MiB package/
32MiB per-CSV-and-import limits still fail the whole operation without truncation.
Captured wrappers cannot be copied to authorize formatting, and the ten-source
formatter refuses a full-instance capability rather than confusing its scope.

The new private-instance-csv.v1 package has193 files:189 CSVs, dictionary, exact
spreadsheet escape map, neutral SQL and a size/SHA256 manifest. The manifest
records the snapshot, all-reviewed-column coverage, source count and canonical
registry/routine/schema fingerprints. This is reviewed application-column
coverage only: auth-provider schema, encrypted credentials, original byte stores,
OS secrets/account access and complete relational/reference closure are not
declared covered. completePortableExport/referenceClosureVerified/completeBackup
remain false. Credential and provider-proof exclusions retain their existing
canonical meaning; no previously excluded value is selected.

The existing explicit private command supports request schemaVersion2 with
sourceSet:instance_sources, plus its existing leaseBusinessId, databaseUrl,
rootCertificateFile and outputParent fields. Request schemaVersion1 remains the
ten-source operator profile. Unsupported/extra fields refuse before connection.
Production Linux owner-only files/TLS and test-only loopback/Windows seams are
unchanged. Instance delivery creates a fresh crest-instance-export folder; no
existing output is replaced. File paths are fixed by the trusted formatter.

instance_reimport.sql creates only crest_instance_source text tables and metadata
in a separate empty database. It does not recreate sessions, grants, application
schemas, workers or posting logic. The single transaction refuses an existing
target schema. Original types/keys remain metadata; text-key sorting need not
equal numeric source-key sorting, so independent comparisons use full row
multisets rather than hiding value differences behind a type conversion.

## Declared relationship map

The follow-up capture lists every declared foreign key originating in the189
application tables. Ordered source/parent columns, match semantics and constraint
validation state come from the same snapshot. For fully included internal keys,
read-only counts require no missing parent and enforce SIMPLE/FULL null semantics.
An orphan refuses the entire capture. External parent sources and keys involving
credential-excluded columns are explicitly classified and are not queried or
quietly counted as closed. Required FK column lists are cast to PostgreSQL text
arrays; the existing driver does not register name[] as a string-array type.

Each source dictionary and neutral-import metadata row includes its relationship
map. The manifest counts verified/excluded/external declarations separately.
This verifies declared source-snapshot relationships, not all polymorphic IDs,
original bytes, provider identity recovery or typed application rules. Overall
referenceClosureVerified therefore remains false even if every declared internal
FK is included. Neutral text import does not activate these application FKs.

cases retain normal constraints. The expanded native case passes on88abc20,

and test.log. It retains full193-file capture/delivery/reimport, three businesses
