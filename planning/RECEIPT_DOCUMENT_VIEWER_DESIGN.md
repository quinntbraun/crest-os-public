# Verified receipt document viewer

November17,2026. The latest audit asks for an intentional receipt viewer with close, fit-to-width and accessible zoom. The existing inline private preview and all original upload/recovery/download controls are retained.

Enlarge receipt preview opens a native modal over the verified preview already held in memory. It displays the expense identity, recorded amount and payment date. Bounded zoom uses CSS data states, preserving the strict no-inline-style policy. Zoom, fit and closing do not call an API or alter the original. Native dialog behavior supplies modal focus containment and Escape; closing returns to the enlargement trigger. The inline Close preview still restores the original record trigger and revokes its URL.

The parent retains ownership of private bytes and object URLs. Existing suspension, record change, pane visibility, disclosure closing and unmount clearing remove the viewer as well. A failed browser image display is distinguished from successful preview display and offers closing/reopening; it is not treated as a verified original document. The viewer explicitly identifies itself as a preview image, with full original download remaining in the saved receipt controls.

No decoder, MIME validation, schema, upload reservation/publication, receipt source bytes, accounting treatment, original retry, export or permission changes. Real original-format handling, physical iPhone and exact-source release acceptance remain required. Verification will be recorded after execution.

The viewer explicitly labels its amount as the recorded expense and the date as paid on; neither is presented as an OCR reading or a verified amount/date match to the receipt.
