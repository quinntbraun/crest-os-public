# Customer editor and interrupted saves

This slice consumes PR68 without changing its backend, migrations or runtime opt-in. ADR22 prohibits customer-data offline caching. Customer source rows, history, searches, drafts, proof and original retry payload exist only in memory. Backgrounding, page departure, disposal and explicit reload clear them and cancel owned work. Late responses cannot repopulate a suspended view. Browser storage contains no contact draft, payload hash, credential or proof.

Before a first save, refresh session/proof/context and require the original business/sign-in/epoch and ready write state. Failure or changed context creates no operation/reference, sends no customer command and clears the private editor. It never substitutes a newer epoch. Before dispatch, one verified per-tab sessionStorage record retains only schema version, configured business UUID, non-authorizing sign-in binding and original operation/customer/version/recovery-epoch reference. No overwrite, expiry purge, automatic lookup, retry, ID replacement or epoch substitution is allowed. Storage is verified before dispatch/retry/removal; failure blocks further editing. This metadata is private and is neither authorization nor a complete backup. Clearing browser data or closing the tab can lose it; cross-tab coordination and a durable server pending queue are not implemented.

Unknown outcomes retain the reference and block new writes. The user explicitly checks the original operation under fresh authorization. A verified committed receipt clears only the matching reference, including after sign-in/recovery changes. Absent is not proof of failure. An identical explicit retry is available only after an absence check, while the original immutable draft remains in memory, and after fresh matching business/sign-in/write/recovery checks. A reload or background event discards that draft. An absent receipt then remains blocked for review; the editor does not reconstruct contact data, guess an abandoned request or silently start a replacement. Resolving such an absent/lost-draft case through a durable fenced operator workflow remains an explicit real-use gate.

Only first-attempt definite input/not-submitted/denied results may clear a reference without a receipt. They cannot erase an earlier uncertain attempt. Operation conflicts stay retained for review; customer/version conflicts require loading and reviewing current records before a new edit. Save results never automatically refresh, replay or merge edits.

Directory search is literal, archived inclusion explicit and pages bounded. Opening a customer obtains current source/history before editing; null and explicit empty optional values must remain distinguishable. Archive requires a reason; reopen explicitly removes the current archive reason while retained history remains. No delete/merge or invented customer-since/source/identity inference.

Controller/store tests and an actual mobile/desktop browser fixture are required. This document records implementation mechanics under ADR22/41, not a canonical policy relaxation. No real-data approval, complete portability, file publication, production deployment, paid service or default runtime activation.
