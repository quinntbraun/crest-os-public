## Scope and decisions

Schema12 adds lock_mutation_authority. Its inputs pin the exact verified local session/actor/provider issuer/subject/session/deadline, opaque credential hash, selected business, expected recovery epoch and fixed server capability/recent-auth policy. READ COMMITTED is mandatory. Actor shared, business shared and local session FOR UPDATE locks precede the recovery-authority shared lock. Membership changes serialize on the existing business root. The session update lock serializes future foreground activity with refresh/revoke and avoids two commands upgrading shared session locks. Locks remain until transaction end.

Full live local/provider eligibility and active membership/capability checks run before recovery lookup. After the authority wait, fresh statements require the exact expected epoch and writes_enabled=true and recheck time/recent-auth/live provider eligibility. A stale epoch, absent root or paused writes returns only RECOVERY_REVIEW_REQUIRED, never the new epoch. Authentication failures do not disclose recovery state. Provider signature/issuer/audience verification remains a mandatory earlier server step; synthetic auth rows are not cryptographic evidence. Provider changes after the last live check remain a distributed-system limit, as with the existing read boundary.

The allowlist is identity.manage, crm.manage, finance.post and export.bulk. Recent authentication is fixed by trusted server route policy; export.bulk always requires the canonical15-minute bound even if false is supplied. No caller-selected capability is accepted by the server request. Future typed definer commands must hardcode their own capability/recent-auth requirement and call the fence themselves before operation replay or writes. This routine alone grants no domain table access, recovery activation, epoch discovery or reusable authority.

Reuse the existing restricted nonlogin session owner, fixed pg_catalog/pg_temp search path and forced-RLS policies. Add only SELECT(active_epoch,writes_enabled) on the recovery root to that owner. Existing lock-only id UPDATE privilege/false write policy remain. Grant routine execution only to crest_web; no command-owner grant is made before a reviewed typed consumer exists. Default-grant/role/forced-RLS drift checks precede DDL. No new role, table, write grant, dependency, operation/audit record or activity update is introduced.

The server-only createMutationTransaction snapshots fixed policy and the request's business/epoch before awaits. It performs fresh SDK/local session verification as background work before opening a database transaction, so provider network work holds no business lock. A dedicated command connection profile uses the same checked-out restricted login/crest_web connection, READ COMMITTED,3-second lock/10-second statement limits,11-second query timeout,12-second idle timeout and15-second transaction/connection deadline. Refresh retains its existing distinct timing. Production connections retain verified TLS. The complete composition also has a35-second abort bound.

The callback receives a frozen transaction scope after the exact five-field fence result has been checked against the request and verified session. Scope queries are trusted static server SQL only; browser SQL, transaction-control statements and external I/O are forbidden callback contracts. Captured queries reject after callback completion; unfinished queries or any failed statement invalidate the scope even if a callback swallowed the failure. PostgreSQL COMMIT must actually report COMMIT: its ROLLBACK completion after a swallowed SQL error cannot become a false success. Raw database/provider/callback errors and causes are suppressed. Only the fixed recovery classification escapes; uncertain commit outcomes are not confirmed and callbacks are never automatically retried. Operation identities/lookup must exist before any future safe mutation retry policy.

A returned context is point-in-time metadata. It is not a GUC/RLS authority or permission to use an unrelated connection. No HTTP business route, default authentication switch or positive domain write is enabled. All new authorities remain paused by default. Tests alone use explicit admin activation in disposable synthetic databases.
