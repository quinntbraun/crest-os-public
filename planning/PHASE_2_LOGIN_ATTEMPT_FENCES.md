## Decision and scope

Schema22 adds provider_login_finishes: immutable, forced-RLS, token-free observations, one per attempt/phase. registration_closed requires an existing app session with exactly one original CREATED source event matching the retained attempt/actor/epoch and any known target. It records registration history; it does not prove final provider verification, HTTP/cookie delivery, browser acceptance, current eligibility or cleanup. stopped_review records a local stop; if an app session exists, it must match that exact source and is revoked through the existing audited revoker in the same transaction as this append. Another device is never selected by subject alone. Epoch changes, disablement and provider loss do not prevent a safe reduction of the original attempt's local authority.

Both phases fence future app issuance for that attempt. A domain-separated nonwaiting transaction advisory lock serializes issue_open_app_session with finish_provider_login, including direct privileged finish INSERT through the invoker guard. Stop-first makes overlapping issuance busy and later issuance denied. Issue-first makes overlapping stop busy; after commit, a later stop revokes the exact original registration. Rollback releases the claim without a finish. A failed finish append rolls back its local revocation, audit and existing schema17 cleanup reference together. Conflicting source identity is rejected without revoking a different row. Exact phase replay returns original JSON bytes/hash, never another side effect or a new authorization decision. Registration closure followed by stop retains both observations; registration replay remains historical after the stop. Direct DML cannot forge a stop for a still-live app session. Updates/deletes/truncates are rejected.

Ordinary web EXECUTE on the old issue_app_session, issue_tracked_app_session and issue_targeted_app_session entrypoints is deliberately retired. Their original SQL is unchanged, and the fixed session owner continues its reviewed internal delegation through21/20/6. Current runtime uses issue_open_app_session; an older app binary's login now fails closed after22 instead of bypassing the local fence. This is an explicit tightening before first release, not a claim of full old-login compatibility. Existing session verification, refresh, logout and business authorization are unchanged. The closed shell's schema range remains0..22; enabled current authentication requires22, and schema rollback remains forbidden. Future deployment must pair the supported current code with22; no production migration or deployment is authorized here.

## Runtime and permissions

The lifecycle retains the immutable confirmed begin context. It issues only through the fenced wrapper, confirms registration_closed, then runs the existing fresh final SDK/local verification before releasing a credential. An uncertain/malformed/cancelled registration finish never permits handoff. On any failure after a confirmed begin, it tries stopped_review with an independent bounded signal before scoped provider cleanup. A confirmed stop includes atomic local revocation if needed. Failed/unknown stop confirmation falls back to revoking only the known allocated credential; provider cleanup is still attempted with known new material. If begin acknowledgement itself was uncertain, no actor context/provider I/O is invented. No automatic password/issue/finish retry is added.

The existing session owner gets SELECT/INSERT on this safe ledger; existing revoker delegation was already granted in schema9. No new role, membership, upstream source privilege or provider DML. Definer metadata and nonlogin/noninheriting owner-role state are reviewed on migration; bad source grants/upstream issuer/revoker configuration leave a pending migration review. Fixed search_path/row_security and UTC/ISO invoker derivation apply. Bodies include source IDs, original identity/epoch, phase, source registration event, known provider ID/local revocation time and database provenance; no credential hash, token, key, code, password, email or raw provider diagnostic. Original UTF8 JSON text and SHA256 make evidence independently hashable; this is not an independent signature or tamper-proof attestation.

The isolated existing inventory definer gets SELECT on the new table only. provider_login_finish_inventory returns1..100 UUID-keyset historical observations under exact actor/issuer, including disabled/old-epoch history. No ordinary web/worker/recovery access to inventory/raw rows, no source/provider writes. Pages are not a complete cross-page snapshot; later inserts behind a cursor need a new sweep. Customer exports gain no global security access; later authorized security backup/export must preserve these original rows/bytes.
