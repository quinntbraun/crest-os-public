# Catalog source portability and recovery construction

Requirement: approved service definitions must retain their original scope and remain portable and recoverable before permanent catalog saves are exposed. This unblocks the service catalog → quote workflow. Completion requires actual PostgreSQL source reads, exact CSV round trips and an encrypted restore into an independent database, in addition to typed interrupted-save resolution and migration adoption. It does not activate a service-save button by itself.

`service-catalog-source.sql` is an **unregistered proposal** applied only after registered43 and the checksum-pinned storage/command proposals in disposable synthetic fixtures. It reuses the existing closed catalog definer and isolated `crest_export` role. Three fixed functions expose tenant-scoped context and UUID-paginated roots/content within a read-only repeatable-read transaction. A domain-specific snapshot token binds both collections. Bounds fail explicitly: 1,000 roots/content rows each, 50 rows/page and 1 MiB/page. Ordinary `crest_web` receives no bulk function or raw table access. No new role, package, HTTP endpoint, registry ordinal or write authority is added.

`formatServiceCatalogCsv` represents every column of both tables, including inactive roots, retained content, private guidance and provenance. It rejects missing/mismatched pointers, sequences, counts, foreign rows and unsupported fields. RFC4180 CSV preserves nullable/empty strings, exact bigint values and six-digit UTC instants; the escape map distinguishes original apostrophes, formula protection and literal null markers. The dictionary explicitly requires integer columns to be imported as text in spreadsheets. Files are owner-only sources, never customer quote documents. Formatting does not prove source origin, audit/actor closure, custody, a complete Crest export or a complete backup; manifests state those limits.

Focused local verification: `npm test -- tests/unit/service-catalog-csv.test.ts`, types and lint. Mandatory native verification: `npm run test:catalog-source-proposal`, after the existing verified database/recovery tools. That fixture checks source drift refusal, least privilege, all 29 live columns, actual trusted saves/edit/archive, cross-tenant/token refusal, empty data, pagination, concurrent snapshot consistency and exact independent CSV decoding. The existing encrypted recovery machinery restores all rows and schema/grants on a separate owned PostgreSQL cluster, excludes a post-snapshot save, and proves restored sessions/epochs cannot write through the paused recovery fence. These synthetic incident fixtures do not establish production old-writer fencing or owner recovery approval.
