## Selection and authority

Trusted server composition supplies immutable actor ID, exact configured HTTPS issuer and a dedicated database profile. Call createProviderCleanupExecutor for the cleanup login and createProviderCleanupOutcomeReader for a separate inventory login. Only fixed parameterized schema24 commands are available. No provider/session UUID, token, broad-user scope, caller SQL, automatic inventory selection or new request identity is accepted. dispatchProviderCleanup accepts1..10 distinct original request UUIDs, copies and normalizes the complete selection before any await, and runs sequentially. Invalid/duplicate/oversize selection fails before work.

The synthetic tests provision random disposable NOINHERIT logins only after closed migration/grant tests. Product code provisions nothing. Every fresh connection SET ROLEs to exactly cleanup or inventory; it refuses an elevated/inheriting/admin login, mixed/indirect capability membership, administrative/inheriting membership options, missing SET permission, or a changed/elevated capability role. This guard is a necessary narrow runtime check, not a complete ownership/direct-ACL audit or defense against a malicious database administrator. Future provisioning must audit direct privileges, ownership/default privileges, credentials, TLS, role configuration and actual hosted provider support. Never reuse the web, worker, recovery or migration login. Provisioning/activation remains blocked and is not implied by synthetic role fixtures.

## Bounds and uncertain outcomes

Each operation gets a new connection,1second connection timeout,3second statement timeout,2second lock timeout,3.5second client query timeout and independent4second cancellation deadline. Execution is one autocommit statement; provider reduction and retained outcome remain schema24's atomic transaction. Read uses only the historical reader. Production TLS requires certificate verification; test URLs must be loopback disposable crest_migrate databases with no URL options. Configuration errors and work errors contain only fixed messages, no raw database cause, SQL, credentials or diagnostics. No logging or HTTP/CLI/scheduler/default-runtime composition is added.

Dispatch independently bounds every item to4seconds and a run to45seconds, including an uncooperative injected executor. Pre-cancelled/unstarted entries remain not_started. Any started failure, malformed receipt, cancellation, denied source or unknown response is conservatively outcome_unknown; stop the run and mark later original IDs not_started. No automatic retry, historical lookup, new selection or new UUID is generated. Cancelling a client cannot prove server rollback. Work already in flight may complete after the caller has stopped; late completions cannot mutate the returned frozen report. Global cross-process scheduling/budgets, leases, durable dispatch journals and shared capacity remain future work.

The independent reader can recover the same original request's committed receipt. Null is only scoped point-in-time historical absence and can race a transaction; never interpret it as proof that a deletion did not happen, fresh eligibility, or permission to create another request. Any later explicitly reviewed execution uses the identical original request, actor and issuer. Schema24 replay returns saved evidence without deleting again, including after a provider row reappears. No automatic password retry, unknown-attempt expiry or timeout closure.
