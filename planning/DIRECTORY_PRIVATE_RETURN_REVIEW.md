# Directory record and inclusion return

Original S13 applies to ordinary record opens, not only links that arrive with an ID. Customers, Vehicles, Leads and Services previously kept normal directory selections only in loaded private state. Suspending that state lost the record selection and reset archive/lost/inactive inclusion. Services also lacked a record-ID page consumer.

The four screens now remember only a validated opaque record UUID and the existing finite inclusion choice in navigation. Customers also project their existing selected section. The common URL serializer uses the same fixed sign-in return destinations and validation as other contextual links; names, custom searches, draft fields, prices, notes, versions, credentials and pending-original references are excluded. Services now has the matching validated page consumer. The lead device-access link uses the same contextual sign-in component.

Hiding or restoring a page still clears every controller's private rows, selected record, draft, history and transient original. After an explicit fresh directory access check, Reopen selected retrieves the record through its existing authorized reader. A hard reload uses the existing deep-link behavior and fresh authorization, including the new Services equivalent. No private draft is restored, no save is automatically sent and an unresolved original blocks normal reads/editing as before. Explicitly creating a different record, searching or returning to the directory clears the open-record pointer; the finite inclusion choice remains. Existing in-memory Back/focus/scroll and unsaved-draft confirmation behavior is preserved.

Directory load accepts an optional boolean inclusion scope, defaulting to the original active-only scope. It changes only the existing bounded list request after fresh session/context and pending-original checks. It does not broaden server permissions, change pagination, retain custom search text or change any save/retry/lookup/retirement payload. No schema, SQL, financial rule, capability or provider activation changes.

The 190 focused controller/navigation/page/sign-in checks pass, including actual page-prop round trips for all four destinations, invalid/duplicate filters/IDs, restored inclusion scope and the inability to bypass an unresolved original save. The new journey seeds four fictional records through genuine registered commands, discards unsaved private markers through pagehide, checks explicit reopen, directory inclusion request scope, actual page reload and missing-cookie denial, and conserves record/operation/audit rows with zero subsequent save dispatches. It does not fabricate authentication or financial responses.

This advances the original S13/S06 scope; it is not a final sign-off for every alternate origin, state, zoom, installed release or physical iPhone requirement.
