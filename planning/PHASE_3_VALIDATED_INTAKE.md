# Validated private file intake

2026-10-24. Implementation of the existing ARCHITECTURE upload sequence and SECURITY 5 isolation contract. No schema/canonical changes, service provisioning, production activation, spending or real data.

## Delivered path

The credentialed file-job coordinator reads staging once under the existing 25 MiB bound, seals and hashes that snapshot, invokes the isolated decoder and checks its original digest/type/size before writing anything durable. It seals the preview and metadata before storage awaits. Original and preview use separately reserved private keys, atomic conditional creation and independent final read/hash verification. Original bytes never shrink or change. Preview writes accept only JPEG up to 8 MiB. No delete, overwrite, automatic retry, signed GET, public URL or Available publication is added.

On preview failure the original remains private; on lost PUT response its outcome stays uncertain. Callers must retain both reserved candidate keys and the dispatch ID, even when the call rejects. No result means neither absence nor permission to discard or automatically retry an uncertain candidate. A successful pair is named PrivateValidatedCandidate and returns metadata/digests without payload bytes. Typed current-session/parent/attempt/lease/recovery-epoch publication remains a separate transaction requirement.

## Local operator/CI sandbox transport

The local adapter is an explicit transport for the already implemented sandbox contract. It is not a production host selection. A trusted operator supplies the content-addressed image ID of the reviewed, locally loaded release and a unique previously recorded dispatch UUID. The adapter never accepts a tag, arbitrary command, executable, mount, provider URL or adjustable isolation limit. Docker's local Unix socket and an empty private CLI configuration are fixed; inherited credentials, Docker contexts and loader/environment overrides are not forwarded. Never give the web process or decoder a Docker socket. Production dispatch on the selected host remains unconfigured; do not assume a Render cron can spawn containers. A changed production trust/deployment boundary requires the documented architecture review/ADR and free-first cost/restore proof.

Create without starting, prohibit image pulls, suppress persistent container logging and inherited healthchecks, override the entrypoint to the known Node executable, and inspect exact image/container/dispatch-label ownership before starting. Run the same-release worker with no network, read-only root, node UID, no capabilities, NoNewPrivs/default seccomp, one CPU, 32 PIDs, zero swap, 128 MiB V8 heap and fixed scratch. HEIC uses 1 GiB / 320 MiB scratch; other formats use 512 MiB / 64 MiB scratch. Admission inside each worker remains mandatory. No credentials or original bytes are placed in argv, environment or disk scratch on the broker.

Use a monotonic 60-second total transport budget with time reserved for cleanup, bounded stdout (12 MiB result / 64 KiB control), discarded stderr and cancellation. Check process exit/OOM/running state as well as the exact version, source hash/size/type, bounded geometry/pages, canonical base64 and independent preview hash. Do not decode untrusted images in the broker. Hold success until the exact verified owned ID is force-removed. Unknown create/ownership/removal outcomes withhold results; the supplied dispatch ID identifies the retained attempt for explicit reconciliation. Do not start/delete an unverified container or sweep by a broad name/label selector. No automatic uncertainty reconciliation or durable task/reservation table is claimed by this slice.

Each adapter/intake instance permits one in-flight job; the future durable queue must additionally enforce global concurrency, lease/epoch fences and memory/capacity limits. Staging/storage operations retain their 60-second bounds; intake has an overall five-minute cancellation budget. Production capacity and end-to-end job authority remain unproven.
