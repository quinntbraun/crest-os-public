# Schedule navigation context

Schedule task links now carry a validated date range, day/week/month/custom view, calendar/custom-range disclosure state and originating job. Optional bounded scroll position and viewport width support an exact return when the original row is present and the layout is unchanged. This extends the existing in-page agenda return; it does not replace its original source-button/focus behavior.

The shared `ScheduleLink` renders an ordinary anchor with its final destination before hydration. Schedule pages provide context to nested links; the three existing button-driven work/change/cancel departures use the same destination builder. Work, completion, cancellation, interruption, recorded time, mileage, travel, booking and service-arrangement pages carry context onward. Existing job/trip/kind parameters and fragments remain intact. Non-Schedule destinations remain unchanged.

The URL contract accepts only `plannerFrom`, `plannerThrough`, `plannerView`, `plannerCalendar`, `plannerRange`, `plannerFocus`, `plannerY` and `plannerWidth`. Repeated/malformed required fields, impossible or oversized ranges and misleading calendar modes are refused. Invalid optional origin fields are discarded. No arbitrary return URL, customer name, address, draft, resource snapshot, credentials or financial data is copied into the context. There is no new persistent browser storage, command, schema or permission. Business-zone date validation and fresh authorization still occur through the existing reader; a URL is not authority to read a job.

Returning to the agenda loads fresh records and restores the actual matching row's focus. Scroll is reused at the same viewport width, with a visible-focus fallback for changed geometry. A missing origin on an incomplete page remains eligible for restoration after the user loads more; there is no unbounded automatic page replay. A removed/moved origin falls back to the agenda heading. Existing private-page suspension clears records and pending focus restoration on hide/pagehide/bfcache restoration.

This is an incremental S03/S13 implementation. Paginated-origin, changed-record, outside-Schedule customer/vehicle date forwarding, broader configured task states, actual zoom, installed/owner and physical-device acceptance remain required. Do not infer final audit sign-off from the shared link implementation or one browser journey.
