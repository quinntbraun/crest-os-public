# Private object storage boundary

2026-10-24. Phase3 implementation under DATABASE section6, SECURITY section5 and ARCHITECTURE section16. These execution notes do not amend canonical rules or authorize a service account, deployment, real data or spending.

## Implemented boundary

`src/files/private-object-store.ts` uses exact-pinned Apache-2.0 AWS SDK packages for the existing R2 Standard/S3 architecture. The production factory accepts explicit server credentials and a validated R2 account/bucket; it fixes HTTPS, region auto, single-attempt operations and bounded transport timeouts. It has no ambient credential discovery, public bucket/custom-domain endpoint, delete, overwrite, listing, signed GET or browser runtime integration. Injecting an SDK client is a trusted server/test composition seam, not an untrusted URL setting.

- An upload capability signs only PUT, one fresh random `staging/business/attempt/random` key, declared allowlisted content type and600 seconds. Explicit `forUpload()` is the bearer handoff; ordinary JSON serialization throws. Do not log, persist or export that URL. The returned expected byte count is ticket metadata, not a claimed PUT size restriction. Authentication, typed parent authorization, durable attempt expiry/rate limits and recovery state must precede issuance in the later application integration.
- Staging intake checks actual response length, incrementally counts/hashes bytes under25 MiB, and rejects mismatch, oversized, incomplete or interrupted reads. It returns the exact bounded snapshot for an isolated validator. Header MIME and ETag are not validation/checksum evidence. A60-second operation deadline includes response-body consumption; caller cancellation destroys the stream. Errors have stable codes without raw SDK exceptions, causes, request URLs or credentials.
- The worker must reserve and durably record a fresh `originals/business/random` candidate key before attempting a write. `writeOriginalCandidate` copies its byte input before its first await, independently verifies the expected SHA-256, writes with atomic `If-None-Match: *`, then independently reads/counts/hashes final stored bytes. A replaced staging upload or mutable caller buffer cannot change the sealed original. Duplicate/concurrent key creation fails rather than replacing history. No automatic write retry or deletion exists. A lost write response is `OBJECT_WRITE_UNCERTAIN`; an absent immediate read is never proof that an in-flight PUT failed. Retain candidate identity for reconciliation/inventory, including errors after a successful PUT.

The returned digest proves only a byte transfer against the invoked storage adapter. It is deliberately not an Available attachment, format-validation verdict, public read capability, database publication or authorization result. No customer/file route is exposed and the default runtime remains closed.

## Memory and lifecycle limits

Intake streams incrementally but retains at most25 MiB of payload for the later decoder; chunk consolidation and a sealed write copy require additional bounded memory. This is not an unbounded stream or a zero-copy/capacity claim. Worker concurrency, decoder isolation/memory/CPU/decode limits and peak-memory measurement remain integration gates. The adapter must be used in the isolated file worker rather than accepting arbitrary browser bodies into the application process. The production factory owns its SDK client and supplies `close()`; an injected client is owned by its caller.

There is intentionally no generic polymorphic attachment-parent table or root file cabinet: canonical attachment links require real typed domain FKs. The worker/DB integration must enforce current actor/session/typed parent permission, attempt/lease fence and recovery epoch again at publication, independently of storage success. Late/orphan candidates stay private and are reconciled; no automatic original deletion is permitted. Actual R2 bucket privacy, least-privilege credentials, CORS and absence of alternate public access must be proven during owner-authorized setup.

## Evidence and remaining work

`npm run test:private-files` runs the actual AWS SDK against native loopback HTTP and Readable streams, with synthetic generated credentials and bytes. The fixture independently recomputes PUT SigV4 HMAC, rejects changed method/key/content type, and injects corruption, truncation, missing lengths, oversized responses, stalled bodies, cancellation, concurrent key collisions and a committed PUT with a lost response. It also verifies the exact25 MiB boundary, sealed caller buffers, reused staging PUTs, independent final hashes despite fake ETags, redacted errors and refusal of invalid namespace/type/size/configuration. The fixture models only the operations required for these tests; it is not a full S3 server or actual-provider proof. The suite is mandatory in the protected aggregate alongside every existing gate.

Remaining Phase3 work: isolated JPEG/PNG/HEIC/PDF decoding and active-content rejection; immutable validation-version evidence and previews; typed attachment schema/routes with durable limits, leases and epoch fencing; fresh-session authorized streaming reads including Range; file inventory/basic export manifest and encrypted compatible object/configuration/key/image recovery; independent vault/heartbeat/incident authority. Real synthetic iPhone HEIC samples, actual configured R2 conformance/privacy and full recovery/capacity proofs remain required before pilot. No file is declared safe or Available by this slice, and no paid/cloud account is needed for its native tests.
