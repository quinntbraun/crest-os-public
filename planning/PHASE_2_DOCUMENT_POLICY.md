## Decisions

Every request receives a fresh Node randomBytes32 base64 nonce before rendering. Proxy overwrites caller-supplied x-crest-nonce and Content-Security-Policy and removes legacy x-nonce/report-only request hints. It passes generated request headers upstream using NextResponse.next({request:{headers}}); it never copies credentials/request headers to public response headers. The response carries the same enforced CSP. Next reads the request CSP to apply nonces to its framework scripts; the root layout requires a canonical matching internal nonce and script directive and explicitly forces dynamic rendering. A missing or mismatched context fails rendering with a fixed error. The nonce is public document metadata, not an authentication credential.

Proxy applies to all paths/methods, including API/error/static requests and caller prefetch hints. There is no path/header matcher that can bypass nonce generation. Framework static assets under the reserved /_next/static/ prefix retain Next's own cache decisions; their response also carries policy, which grants no authorization. Missing static resources must still return uncached404 responses. All other responses receive private/no-store/max-age=0, CDN-Cache-Control:no-store, Surrogate-Control:no-store, Pragma:no-cache and Expires:0. The framework may add stricter cache directives. Current liveness remains a generic JSON process check with no-store. Existing private JSON handoff serializers retain their separate deny-all policy; reconcile route/Proxy response policy when dispatch is wired. No shared page/nonce cache, static protected-page generation or partial prerendering is permitted by this layout.

Production script/style sources are self plus the response's unpredictable nonce; script/style attributes are denied. Self-hosted framework chunks continue to load. There are no external script hosts, unsafe-inline, unsafe-eval, wildcard sources or strict-dynamic delegated script trust in production. Frames, objects, base changes, workers and media are denied; forms/connect/fonts/manifests remain self-only; images permit self/blob for eventual controlled private previews. No arbitrary customer URL fetch or public file access is introduced. Future rich text, styles, worker/PWA, upload/storage or third-party code changes must review this policy rather than loosen it globally for convenience. CSP is defense in depth: it does not replace escaping, trusted code review or authorization and cannot protect against a fully compromised application server.

Only an actual NODE_ENV=development build receives the debugging unsafe-eval and WebSocket connection allowances needed by the framework. It still receives random nonces and no unsafe-inline. CREST_ENV=test, an HTTP request/header, or any missing/unrecognized runtime mode cannot weaken a production build. The policy factory itself rejects unrecognized mode arguments. Development uses synthetic data only. HSTS and upgrade-insecure-requests are deferred until HTTPS is verified; no insecure cookie exception is added and no real-data/production route is opened.

The current shell has no sign-in interaction. A small404 page uses existing CSS classes and a Next Link instead of relying on framework inline error-page styles that the policy forbids. Browser tests also exercise return navigation from that page. These checks cover production rendering/framework bootstrap and browser CSP enforcement, not MFA UI, real HTTPS cookie behavior, complete hydration/navigation for future screens, membership/capability or business authorization. Header Proxy never verifies identity, trusts an ingress address or renews authentication/activity; future routes must still call the guarded browser-session orchestration and authorize every actual operation independently.
