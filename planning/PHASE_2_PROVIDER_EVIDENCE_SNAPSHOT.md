## Context and pages

provider_evidence_export_context(actor,issuer) returns schema1, scope=retained_provider_ledgers, actorId, exact providerIssuer, observedAt, snapshotToken and ledgerCounts. Counts are exact decimal strings, including zero, for inventory_observation (schema19), login_attempt (20), login_target (21), login_finish (22, both phases), cleanup_request (23) and cleanup_outcome (24). All matching historical rows are included regardless of current actor/epoch/provider state; no state-based filtering, deletion assumption or automatic resolution. Counts require one scoped scan per ledger and should be captured once by a future collector, not recalculated per page.

The lower-case64hex snapshotToken is SHA256 of a domain-separated JSON array containing the original actor UUID, exact issuer and pg_current_snapshot textual visibility state. Bound underlying snapshot metadata to16384 UTF8 bytes; larger snapshots require review rather than truncation. This opaque fingerprint catches mixed scope or changed visibility. It is unkeyed and non-authorizing, not a signature, unique transaction/generation ID, database-identity attestation, retained snapshot handle or cross-connection/restart ticket. Identical visibility can produce the same fingerprint after transaction boundaries; callers must still own one pinned connection/transaction. A copied issuer string cannot prove which database produced evidence. Do not use this token to grant access or resume a released export.

provider_evidence_export_page(actor,issuer,snapshotToken,ledgerKind,afterId,pageSize) validates the fingerprint and a fixed kind allowlist, then selects one indexed exclusive UUID page in ascending source-primary-key order, size1..20. No caller SQL, dynamic query, provider/user scope or arbitrary table name. Output is record_id, original canonical_evidence and evidence_hash only. A private internal cursor selects one of six static queries, fetches at most20 rows, verifies each SHA256 against exact original UTF8 text and enforces the original8192-byte cap (262144 for inventory observations). The cursor is closed before return and never exposed to callers. A wrong hash/oversized/null source fails the entire statement; it is never filtered, silently omitted, repaired or replaced by JSON serialization. No parsed projection duplicates or rehashing into new evidence.

Pages bound body payload to at most about5MiB for inventory observations, excluding PostgreSQL/driver overhead; no hostile-protocol or global memory bound is claimed. Other kinds are smaller. The database routines alone enforce no export-wide time/concurrency budget; those belong to the future bounded collector. Regular source SELECT locks do not take producer/provider row/advisory locks. The snapshot tests require concurrent source capture/request/cleanup to complete with a bounded writer statement timeout. Standard transactional DDL locks still apply; hosted migration/drain/capacity proof remains required before production index creation.

observedAt is the context statement start in UTC, not current provider sampling or exact snapshot acquisition time. Repeatable-read visibility begins at the first data statement; future composition must capture context first and retain its original timestamp/transaction throughout. Repeated context calls can have later observedAt values while retaining the same visibility. Counts and pages are comparable only within that owned snapshot and configured scope. A new generation after failure needs a fresh context and independently identified output; never mix pages across generations. Empty pages mean no further rows in that declared scope/snapshot, never global orphan freedom or safe closure.
