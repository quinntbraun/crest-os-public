## Decisions and trust boundary

Use Node's maintained cryptographic random generator for32 opaque random bytes and standard SHA256 of their canonical43-character base64url cookie value. No identity/session ID is embedded, no password or custom token cipher is implemented. The server-only credential material blocks JSON serialization and exposes explicit cookie-response/hash-storage handoffs with defensive hash copies. It issues neither a database session nor an HTTP cookie. Existing SECURITY2 cookie flags and lifecycle requirements remain mandatory at future routes.

crest_commands.revoke_app_session(bytea,uuid) accepts only a32-byte credential hash and operation ID. It locates and locks the exact unrevoked session under READ COMMITTED, derives actor identity from that row, increments its version and revokes it. Existing immutable triggers clear encrypted provider tokens/key_id and append safe retained history in the same transaction. Unknown/revoked credentials return the same void result without another write/event. Concurrent duplicate revocations serialize, recheck and become no-ops. Invalid SQL inputs or stale isolation reject. There is no session ID/actor parameter, provider call, positive authorization, arbitrary SQL, token return or business mutation.

Revocation reduces global security access, including for expired/disabled/epoch-invalid sessions and during provider outage. It does not require a live provider, active tenant or business write/recovery epoch. This follows the global security-session contract in DATABASE2/SECURITY2 and ARCHITECTURE's separate login/MFA/security controls; it is not an exception permitting business-data mutation without the recovery fence. Possession of a stolen cookie can revoke that cookie's session, never issue/extend/read one. Unknown/already-revoked results avoid a direct existence response, but no constant-time database lookup/timing-oracle guarantee is claimed. A database hash is sensitive credential-derived material and is never exposed/audited/exported.

The existing NOLOGIN/NOINHERIT/non-bypass crest_command_owner owns the fixed pg_catalog,pg_temp-path SECURITY DEFINER routine with row_security=on. No memberships/CREATE rights remain. Only five app-session columns are selectable, only revoked_at/version/updated_by/operation_id updatable; no token ciphertext or provider ID can be selected. Its UPDATE RLS check permits only revoked rows with cleared secret fields. It has INSERT-only access to existing session_events for the invoker trigger. App roles get only web EXECUTE on the command, never table grants/RLS. No provider/worker/recovery role can invoke it. Migration preflight rejects owner-role/table boundary drift rather than adopting it. This is the first narrow command-owner grant; future routines sharing this owner must review that combined authority and their own request/tenant guards.

The server adapter accepts the raw credential, computes its hash, generates the operation UUID and opens a fresh restricted crest_web connection. As with the live provider reader, production requires certificate-verified TLS and rejects URL query overrides; test targets are owned loopback crest_migrate databases only. Runtime login must be LOGIN/NOINHERIT/non-admin with membership only in crest_web. No privilege fallback. Connection/statement/lock/query/whole-operation bounds are1s/1.5s/750ms/2s/3s. Errors are fixed and omit credentials, SQL values and driver causes; cancellation closes the connection. No cross-request authorization cache, provider call or pooling is added.

Success means the autocommit revoke command completed, not that a provider session was signed out. Timeout/disconnect can leave an uncertain commit outcome: never report logout success merely because a request failed; retrying local revocation is idempotent. Future logout must commit local revocation first, then attempt scoped provider signout and clear the cookie under the required same-origin/CSRF controls. Clearing a browser cookie alone is insufficient. Existing provider/local/tenant checks remain necessary on every protected request; historical ciphertext or valid provider JWT cannot resurrect the local session. This slice exposes no HTTP logout route and no complete logout/issuance UI.
