Implementation decision for DATABASE3's separate owner-exclusion and current-billing rules: billing selection is an explicit independent boolean, never inferred from owner/keeper or VIN/plate. The future command must require an explicit selection; the old minimal association draft parser does not supply or default it. A keeper can be the agreed billing customer while another associated person owns the vehicle. This is directory selection only: it creates no bill, changes no job or financial counterparty, and never rewrites historical commercial/customer/photo snapshots. Intake may leave billing unselected. Periods use explicit six-digit UTC microseconds and half-open `[valid_from,valid_to)` bounds. This permits an atomic transfer at one exact instant; end equal to start is an empty retained period under the existing end>=start contract. No Date conversion or millisecond rounding. The pure overlap/containment helpers validate input scope and original fields, but database constraints remain mandatory for concurrency and direct-write integrity.
