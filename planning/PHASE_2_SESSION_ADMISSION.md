## Decisions and ordering

SECURITY4 requires ordinary mutations to be limited to120/minute/session with durable TTL state. The ordinary bucket is shared by future ordinary protected mutations and the currently server-only session-proof reissue. It is not per endpoint/tab/app process. Login retains the separate5/identifier and20/IP per15-minute limits; its initial proof issuance is part of login, not ordinary mutation. Logout is authority reduction and receives a separate120/minute/session allowance so ordinary exhaustion cannot prevent local revocation. This is a documented initial technical bound for logout, not an increase in the120 ordinary-mutation allowance. Logout exhaustion lasts only until the rolling minute expires; it neither borrows ordinary capacity nor creates a permanent account lock. Recovery/upload/export limits retain their canonical separate policies and are not implemented here.

The server chooses exactly ordinary or logout; no browser field/route option selects the bucket. Both use the same existing opaque credential digest and resolve the durable session ID. Unknown credentials allocate no state. A work reservation is explicitly not authentication: existing expired/revoked/disabled/epoch-invalid sessions can reserve work but still fail fresh positive verification. This permits retained-proof local logout without weakening eligibility. Future ordinary business work must validate Origin, synchronizer proof, fresh provider/local state, tenant/capability and transactional recovery/operation/audit fences as applicable. Direct SQL or adapter success never replaces these controls.

Each call locks only its existing app-session row, captures database time after the lock, removes at most240 expired rows for that session and counts admissions newer than now-minus60seconds in the chosen bucket. With120 retained per bucket in normal operation, state is bounded per session. All admitted attempts count even if subsequent verification/provider/business work fails. Rejections append nothing and do not slide a lockout deadline. This is a rolling window, not a fixed-minute reset. Future timestamps remain counted after a backward clock step rather than creating fresh capacity. Clock health, maintenance and capacity measurements remain production gates. No claim of a measured public DDoS limit is made.

The function requires READ COMMITTED. Concurrent calls for one session serialize; another device/session can proceed independently. It never locks an actor/business after the session root or modifies app-session columns, version, authentication/recent-auth/activity/trust/deadlines/provider ciphertext or domain audit. Refresh/revocation may briefly contend on the same session root, but no admission lock is held across SDK/network work. The existing restricted adapter bounds remain1.5s statement/750ms lock/2s query/3s operation and1s connection establishment. A lock timeout, cancellation, database failure, invalid runtime role or uncertain outcome fails closed. Do not retry/refund uncertain admission automatically.

The server adapter reserves in its own committed autocommit operation before expensive/downstream work. It hashes canonical opaque credentials, sends only the digest plus an allowlisted server bucket, clears its temporary digest on success/failure, accepts only an actual boolean result and masks raw exceptions. A committed admission survives an unrelated later domain rollback or caller failure. SQL rollback of an uncommitted reservation removes its row; therefore future domain transactions must not absorb this reservation or claim rollback refunded an already committed attempt.

Browser proof reissue requires Origin first, reserves ordinary capacity before provider verification/refresh, then executes the existing verify/bind/verify flow. Exhaustion cannot return fresh proof/evidence or cause SDK work. Logout verifies Origin and retained session-bound CSRF before reserving logout capacity, then commits local revocation before best-effort provider signout. Invalid Origin/CSRF does not consume another session's allowance. Failed auth/provider work can consume an allowance but cannot return positive evidence. Existing server-only cleanup paths may still revoke unexposed sessions directly; endpoint admission must not prevent mandatory issuance-failure cleanup. No HTTP route is opened by this wiring.

## Privileges, retention and validation

The new table is private, owned by crest_schema_owner and forced RLS. It stores only UUID admission/session IDs, the bucket and a database timestamp: no raw cookie, CSRF proof, email, IP, password, provider token or business data. Existing closed crest_session_owner gains SELECT/INSERT and expired-only DELETE for this table; it gains no UPDATE/TRUNCATE/trigger/maintenance grant or membership/schema CREATE. The function has fixed pg_catalog,pg_temp search_path and row_security=on; web receives EXECUTE only. Other browser/worker/recovery roles cannot read/write its table or call the routine. Preflight rejects drifted session owner role/membership/schema rights or unprotected parent table.

Logical TTL is60seconds; bounded physical pruning runs only for the called session. An inactive session's expired rows can remain until controlled maintenance/retention; no guaranteed60-second physical purge is claimed. There is no runtime whole-table cleanup/delete escape. Before production, scheduled pruning, backup retention and full operational exports must include this nonfinancial state. Do not delete session/audit history to reset a rate counter. An exceptional privileged backlog is pruned in240-row chunks without counting expired rows. No financial/domain journal is generated for resource admission.
