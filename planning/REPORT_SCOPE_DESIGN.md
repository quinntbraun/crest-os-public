# Financial report scope and visual hierarchy

The design audit identified report identity, date scope, currency, coverage, snapshot freshness and export controls as visually fragmented. Trial balance, recorded balance sheet, income statement, customer funds and receivables now use a shared report header.

The compact identity row retains the report period and a textual coverage label while scrolling on sufficiently tall screens. An open nested balance sheet owns that row so two sticky headings cannot overlap. Choosing one of its accounts closes the read-only sheet and focuses the journal filter, restoring the parent report context. Detailed metadata and export controls are grouped immediately below it. Incomplete trial/balance-sheet/income coverage remains explicit beside the results. Customer funds and receivables use neutral posted-scope labels; neither implies that opening balances or legacy records are covered. Existing warnings, numeric calculations, posted history, read authorization and exact CSV content are unchanged.

Snapshot time is displayed in the report's server-supplied timezone. The original full timestamp, including fractional precision, remains in the time element's datetime/title. Formatting falls back to the original timestamp rather than guessing a timezone or inventing freshness. A checked snapshot is not labeled as a live balance or reconciliation approval.

The customer-funds parser already validates observedAt and timeZone but previously omitted them from its returned view. It now retains those validated fields so the UI can show the actual snapshot identity. This changes no schema, grant, business rule, money amount, CSV format or report coverage. The existing metadata/amount/lineage unit case asserts that these values survive without rounding or substitution.
