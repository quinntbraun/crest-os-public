## Scope and decisions

Schema13 creates crest_private.operations and crest_private.audit_events, both owned by the restricted nonlogin schema owner with enabled/forced RLS, no policies and no runtime grants. Default-privilege/role/root-RLS drift checks precede DDL. The new trigger routines are invoker functions with fixed pg_catalog/pg_temp search paths and no PUBLIC or runtime execution. No role, table owner bypass, definer grant, generic GUC authorization or business route is added. Even the table owner sees no rows through ordinary forced-RLS queries. Disposable admin fixtures exercise invariants without disabling RLS; they are not authenticated command APIs.

Operations retain a random row UUID, business-scoped operation UUID, actor, command type/schema, pinned recovery epoch, SHA-256 payload digest, provenance, stable result/schema and recorded completion time. The unique business/operation key provides database claim serialization. It does not by itself implement authenticated replay, payload-hash comparison, canonical typed payload construction or safe retries. Only a pending claim may be inserted. One transition to committed may set its result; identity/provenance cannot change during that transition. Subsequent updates, deletion and truncation reject, including result rewrites. Pending is strictly transaction-local work, never a durable processing status: a deferred constraint trigger inspects the final row and requires committed state plus at least one linked audit event before commit. Rollback removes the claim with its work. Successful tombstones have no TTL or cleanup path.

Audit events require the exact business/operation/actor composite FK, same-business actor/creator membership, matching operation origin/import provenance and a positive entity version. They lock the claim and accept inserts only while it is pending, so completed operations cannot accumulate later audit rows. Each operation may describe several entity changes. Audit update/delete/truncate reject. A mandatory schema1 delta has exactly before/after object-or-null fields, with at least one nonnull side. Entity kind/UUID remains descriptive as allowed by DATABASE2; future domain source FKs and semantic constraints must exist independently. Generic snapshots are not substitutes for relational ownership or money constraints.

The database assigns operation creation/completion and audit recorded times, audit principal and hash evidence. Audit payload schema1 binds event/business/operation/actor/creator, entity/version, action/reason, effective/recorded times, provenance, principal and delta. UTC timestamp strings retain microseconds; bigint entity versions serialize as decimal strings. Hash format pg17-jsonb-text-utf8-v1 uses PostgreSQL17 JSONB text as UTF-8 input to built-in SHA-256. Store the exact hash_input text alongside payload/event_hash, and export it unchanged so any implementation can verify the digest without reproducing PostgreSQL JSON formatting. This is a per-event integrity checksum, not proof against a privileged administrator or an implemented hash chain. Independent external anchors and protected backup/export remain downstream. No previous-hash chain or unproven tamper-resistance claim is introduced.

Result snapshots require a positive matching schemaVersion in an object and are bounded to64KiB of JSONB text; deltas are bounded to256KiB. These are explicit initial storage safety bounds, not truncation rules or permanent business limits. A future typed command needing more must document a reviewed expansion and tests; it must never silently omit history. Exact result shape, meaningful safe before/after allowlists, reason requirements, target ownership and expected aggregate versions belong to that typed consumer. No API accepts caller-selected audit JSON or arbitrary command types. The operation table retains the digest, not the raw command request; hashes/results/deltas must still be treated as private business information. No credentials or provider tokens belong in them. import_row_id is retained provenance reserved for the later reviewed import schema; this adds no import execution or history reconstruction exception.

Historical operation epochs intentionally do not reference the mutable active_epoch value: recovery rotation must not rewrite or invalidate retained evidence. The existing recovery fence remains mandatory before any future claim/replay. This migration does not activate writes or expose/find/replace an epoch. The stored committed_at is the database completion statement's timestamp; PostgreSQL transaction commit succeeds only after all deferred checks. No business success is confirmed before that commit. Storage does not prove that an arbitrary admin supplied every real source change; future typed routines must atomically bind and validate source/audit/result and required outbox work.
