# Saved completion and message-event hierarchy

The latest audit found saved outcomes, message history and invoice preparation arranged as one long document. Saved completion now leads with its retained outcome and time, then open follow-up tasks. Recorded scope and review request have separate reading regions, side by side on wide screens and stacked on phones. Fulfilled, unfinished and cancelled outcomes remain textual labels, with each retained scope and reason shown in full.

An eligible invoice follow-up can move keyboard focus directly to the existing invoice-preparation heading. This does not load financial records, prepare a draft, issue an invoice or send a write. The control is present only when the existing preparation capability and invoice-finalization task are available. The actual preparation remains the separate authorized workflow.

The shared review-message history uses dated event rows with channel, suppression and reason. The existing event timestamp stays primary; the separate recorded timestamp is shown in the summary when its displayed time differs. Exact event and recorded timestamps are always available in a small native disclosure, retaining original precision instead of displaying two apparently identical rounded times. The standalone review outcome is labeled Event time because its contract supplies effectiveAt, not the recording timestamp. Actor names are not invented from identifiers. Owner-confirmed sending retains its exact label and is not represented as provider-confirmed delivery. Original ordering, pagination, failed-read retry, duplicate-page rejection and private-state clearance are unchanged.
