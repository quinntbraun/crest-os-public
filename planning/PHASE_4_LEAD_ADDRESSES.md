# Lead-owned address intake

P02/P03, BR02 and DATABASE3 require incomplete lead locations before customer conversion. The existing customer-owned `crest.addresses` source requires a genuine customer; it cannot hold these reports using an invented customer. This slice retains a separate lead-owned source and its original history. Explicit atomic conversion will later create/select customer-owned destinations and retain mappings without moving or rewriting the intake source. This implements the existing lead resource plan, not automatic matching, a geocoder, a verified scheduling location or a commercial outcome.

The SQL in `proposals/lead-address-intake.sql` is deliberately unregistered pending actual PostgreSQL proof. The disposable proposal helper copies all39 immutable migrations to a separate test directory and appends the proposed40th there. It does not change the canonical registry, coverage inventory, compatibility range or ordinary33-case recovery drill. CI runs12 additional actual database cases after the ordinary lead vehicle suite. Passing these cases will establish proposal behavior only. Adoption must use a new registered migration with verified bytes, updated inventory and same-snapshot encrypted recovery coverage, followed by complete current-source candidate and separate main acceptance. No proposal is a release or production apply.

The proposed26-column `crest.lead_addresses` source has one genuine same-business lead, paired optional exact NUMERIC coordinates, nullable postal fields, exact-location text, instructions, geocode provenance and an optional explicit verification instant. All-unknown and repeated locations remain recordable. Raw empty/null/Unicode input, decimal scale, UTC microseconds, original audit images and bigint versions are retained. PostgreSQL cannot retain a negative zero sign; only that sign is normalized before command hashing, consistently with the existing pure address parser. No numeric rounding or postal/geocode inference occurs.

Existing closed lead command/integrity roles are reused, with forced RLS, scoped policies and no login/membership grants. Saves lock the genuine lead (the same lock future conversion must take), compare the source version, retain immutable parent/provenance, preserve the first archive instant during later archived edits, and write complete deferred before/after audit evidence and an original operation receipt atomically. Current provider/session/owner/crm.manage/recovery authority applies to new saves and replay; paused historical reads remain available. Conflicts, denied authority, audit failures and transaction rollback cannot retain losing operation claims or session-activity changes. Intake never creates a customer/address directory record, changes lead state/version or infers customer/ownership/billing/accepted work.

Pure source/command/page/history contracts, a fixed15-argument private server adapter and reversible source CSV are implemented. Inputs are copied before awaited verification, private values reject JSON serialization, credential hashes are wiped, and uncertain submitted outcomes stay distinct from definite denial/conflict and not submitted. Lookup never resubmits. Directory/history pages are bounded at50/20 complete records and1MiB. Privileged extraction requires one authorized caller-owned read-only repeatable-read snapshot, matching token and genuine business, with archived rows included. Formatting rejects missing, duplicate, foreign, malformed or oversized source collections (1000rows/8MiB), and includes all26 fields, exact null/backslash/formula decoding metadata and byte hashes. These are partial source tools, not a complete Crest export, product import or backup.
