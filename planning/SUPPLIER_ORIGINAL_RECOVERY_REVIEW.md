# Supplier draft original-reference recovery

## Problem and decision

The supplier draft kept its unconfirmed save reference and private payload only in mounted component state. The expense privacy boundary correctly unmounts that component on pagehide/hidden. Returning to the screen therefore lost the original reference and enabled a fresh bill. The existing instruction to sign in in another tab could also trigger that boundary. The original complete expense journey with an added real pagehide/access-return check fails in both browsers on unchanged1dda853: the original-save control is missing. Source stayed fixed and the owned test database was cleaned up. Evidence: .local/design-supplier-suspension-before/result.json and run.log.

Follow the existing opaque expense/invoice reference pattern for this approved V1 workflow. Retain only schema version, business, verified edit binding and the original bill/operation/recovery-epoch/expected-revision identifiers in tab-scoped sessionStorage before any delivery attempt. Never retain supplier, dates, amount, document text, bill splits, payload, credentials or a prepared download. This adds no database schema or accounting rule and sends no automatic save or lookup.

The strict store rejects extra/accessor/prototype/symbol fields, duplicate JSON keys, malformed/oversized references and unsupported original revisions. It refuses overwriting another original, verifies write/removal, and removes only the exact retained identity. Corrupt storage or another business/session blocks a new form and preserves the stored bytes. The component is remounted when verified business/binding changes; no cross-session adoption is introduced.

## Behavior

- After genuine access verification, a restored reference shows an explicit original lookup and no editable replacement. Private details stay cleared. An original with the old in-memory payload can still use the existing explicit unchanged retry.
- A committed original releases the matching stored reference only after its verified result, then displays the actual saved revision. Storage-clear failure does not present an unqualified successful release.
- An absent lookup never means a fresh save is safe. With no private payload left, it opens explicit re-entry using the same bill, operation, recovery epoch and expected revision. The server's existing idempotency, payload matching and revision checks still decide the result. There is no new operation identity or blind retry.
- A definite supplier session denial now uses the existing parent clearing callback for saves and original lookup as well as directory reads. The entire private expense workspace clears; the harmless Suppliers view and opaque original survive. Sign-in uses the existing same-tab return path.

All original saved-draft, revision, duplicate-evidence, financial-event, journal, statement, receipt and export assertions remain. New browser observations exercise a request interrupted before forwarding, exact original re-entry, an actual committed/lost reply, real denied-session lookup, phone/desktop recovery reachability/accessibility, pagehide and actual reload, exact retained bytes, and read-only original resolution. Existing deadlines, provider admission, permissions and financial commands remain.
