# Isolated JPEG/PNG validation and previews

2026-10-24. Implementation under SECURITY section5, DATABASE section6, ARCHITECTURE section16 and TESTING F6/P09. No canonical amendment, schema, business rule, provider setup or production authorization changes.

## Implemented contract

The same release image contains a separate `server/image-worker.mjs` entry point. One invocation reads one original from stdin and returns one private JSON verdict on stdout. The declared MIME is a separate argument. No original filename/path, object URL, credentials, database connection or network fetch is accepted. The caller retains the staged original and candidate/attempt identity; a worker verdict never publishes an attachment or grants access.

JPEG and PNG validation requires an exact bounded source snapshot (1 byte through25 MiB), matching declared/detected type, structural container checks, decoded dimensions through60 million pixels, full pixel decoding and a clean decoder warning history. JPEG framing walks length-delimited segments and entropy scans with stuffing/restart handling; it rejects truncated/concatenated streams and bytes beyond the final EOI. Marker-looking bytes inside valid APP metadata are not treated as boundaries. PNG checks signature, raw ASCII chunk names, lengths, CRCs, IHDR/palette/data/end ordering, contiguous IDAT, unknown critical chunks and exact IEND closure. APNG is explicitly unsupported by this static-image validator. These are format checks, not a claim that every possible embedded payload or malicious file is detectable.

The maintained decoder is exact-pinned Sharp0.35.5 (already locked transitively before this change, now a direct dependency); source bytes remain unchanged. Full raw decoding precedes preview generation rather than relying on metadata or a reduced thumbnail decode. Native cache is disabled and concurrency is one per worker. A small damaged JPEG and CRC-correct extra PNG compressed data can resolve while emitting warnings despite `failOn: warning`; a separate warning latch therefore rejects every native warning. Warning/error text is discarded rather than logged or included in verdicts.

Only the preview is oriented/resized (maximum2048 pixels on either side, no enlargement), composited against white for transparency and encoded to JPEG quality85. EXIF/XMP/ICC/IPTC and orientation metadata are absent from the derived image; private original metadata is retained in the unchanged original. Output records validation version, original size/SHA-256/type/dimensions and separate preview size/SHA-256/dimensions/type/bytes. Preview bytes are bounded to8 MiB; stdout is private IPC, not an operational log or a reusable download capability.

PDF, HEIC and all other formats return `IMAGE_FORMAT_UNAVAILABLE`, never a successful image verdict. PDF active/encrypted/uninspectable rejection and raster previews need a separate isolated implementation. HEIC requires a patched proven decoder and real synthetic iPhone samples; a general HEIF capability flag or AVIF decode is not proof. No fallback silently re-encodes an original into evidence or declares unsupported bytes Available.

## Isolation and lifecycle

Untrusted originals may enter only the isolated worker, not the web process. The decoder module is importable by trusted generated-fixture tests; that import is not a sandbox. The entry point checks admission before loading the native decoder: Linux, non-root UID, zero effective/bounding capabilities, NoNewPrivs, seccomp filtering, read-only root, no non-loopback interface, and explicit cgroup-v2 limits (memory<=512 MiB, zero swap, PIDs<=32 and CPU quota<=one core). Missing/unknown profiles fail closed. These checks verify admission; the external orchestrator must construct and maintain the actual isolation and strip credentials from its environment.

The native CI gate creates the same release container with `--network none --read-only --cap-drop ALL --security-opt no-new-privileges --memory 512m --memory-swap 512m --cpus 1 --pids-limit 32 --user node`, a16 MiB noexec/nosuid/nodev tmpfs and128 MiB V8 heap limit. No host workspace/credential/socket is mounted. The15-second process watchdog covers input/validation/output; native decode/preview operations also have10-second limits. The external caller must additionally enforce a wall deadline, bounded stdout, process/container termination and private error handling; native-heap memory is bounded by cgroups, not merely a V8 option. CI separately records each newly created owned container ID before starting it and removes that exact ID on every outcome.

Production dispatch/transport and platform-compatible isolation are not wired or approved by this slice. The scheduled worker still uses the existing release image architecture; choosing/configuring a production sandbox/orchestrator and proving its controls remains a deployment gate. A Render cron process is not assumed to have a Docker daemon or this isolation profile. No service, spending or architecture migration is implicitly authorized.

## Acceptance and remaining work

`npm run test:image-validation` uses actual native decoding with generated baseline/progressive/metadata-bearing JPEG, RGB/palette/alpha PNG, exact25 MiB/60MP boundaries, corrupt containers/CRC/pixels, mismatched declarations and unsupported formats. It independently decodes previews, checks metadata removal/orientation/white alpha composition, verifies exact unchanged original and preview hashes and rejects caller-buffer mutation races. `npm run test:image-sandbox` repeats the verdict fixtures against the compiled worker in the actual restricted same-release container, exercises the60MP four-channel memory boundary, oversized stdin, ten weakened isolation profiles and a stalled-input watchdog. Both are mandatory alongside every existing gate, before candidate artifacts can publish. Local Docker is unavailable; the container proof must run in Linux CI, not be inferred from direct-module tests.

Next finite work: separate PDF/HEIC support; durable typed attachment/original/derivative and attempt/lease/recovery-epoch publication; current-session/parent-authorized streaming reads including Range; source/object inventory and compatible encrypted backup/recovery. No new file route, schema, Available transition, real customer data or full recovery claim is enabled. Worker verdicts must be validated/bound to the requested original SHA-256 and current authorized attempt/epoch before a later transactional publication. Originals and previews remain private and independently exportable/recoverable.
