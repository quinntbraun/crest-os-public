## Input, output and assurance

It uses Node crypto and the existing credential-free selected-attempt verifier. A type-only collector import erases at runtime; it does not load server-only, pg, a provider adapter or a credential source. No database/provider/network/file I/O, environment lookup, writer, command/route/scheduler, runtime composition or automatic retry. Tests may serialize existing collected values; no file writer/download format is activated by this primitive.

Accept only formatVersion1/assurance=snapshot_bytes_only, a lower-case UUID generation, exact schema1 retained_provider_ledgers context, expected normalized actor/exact issuer, lower64hex claimed snapshot fingerprint, valid UTC capture timestamp, all six explicit decimal counts, declared body-byte count and original record envelopes. Require the collector's fixed ledger order and ascending exclusive UUID order within each kind, exact counts, original UTF8 SHA256 and primary-ID/body binding. No filtering, repair, body JSON replacement or silent coverage reduction. Return immutable original envelopes/context/counts, assurance=internal_consistency_only and ordered per-attempt missingKinds. The original stored body text and hash remain unchanged.

Offline validation cannot independently prove that a trusted collector owned one connection/snapshot, identify the producing physical database/provider, authenticate a principal, prove current absence or establish completeness. Context/generation/counts/fingerprint/hash are unkeyed claims. A forged internally consistent file, including one that removes an entire self-contained lifecycle and adjusts its counts, can pass internal consistency. A unit test explicitly preserves this boundary. No success authorizes login, cleanup, release of funds, Ready publication or restore. Later authenticated private custody, complete manifest/control/coverage and independent recovery verification remain mandatory.

## Bounded JSON and byte policy

Input <=64MiB UTF8 serialized text, including escaped canonical strings and framing; <=1000 records and <=8MiB combined original-body UTF8 bytes. Per-body caps remain262144 for inventory/8192 otherwise.64MiB accommodates worst-case JSON escaping of the8MiB original-body budget plus envelopes; it is not a larger source-data allowance. Validate exact declared counts/bytes without truncation. The reader is for this bounded collection format, not a full-capacity streaming export or complete backup.

A private bounded recursive JSON grammar rejects duplicate decoded object names (including escaped spellings) at every level before any duplicate can collapse. Max depth4,10000 value nodes,32 members per object and1000 elements per array. JSON.parse decodes individual scalar lexemes only. Object name sets are local to each object; repeated legitimate field names in different records remain valid. Use null-prototype intermediate objects. Reject invalid JSON syntax, trailing bytes, BOM, invalid escapes, nonfinite JSON numbers, raw/decoded NUL and unpaired surrogates. Separate UTF8 byte limits from UTF16 string lengths. All metadata and supported nested projections have shallower depth/fewer members; inventory additionally caps observations at its original pageSize<=100.

The parser scans bounded input; budgets do not claim a measured heap maximum or hard real-time CPU deadline. Source strings, decoded projections, records and temporary buffers add memory beyond original-body bytes. Later worker isolation/shared capacity/cancellation/large-part handling remain separate gates. No custom generic parser API is exported or used to replace other repository parsers.
