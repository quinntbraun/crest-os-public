# Private retained-provider-evidence collector

2026-10-23. Implements the bounded source-collection prerequisite of EXPORTS_AND_BACKUPS2/ADR36, after schema26's fixed readers. This supporting primitive does not change a canonical business, financial or provider trust decision. Original canonical provenance and12 amendments, all26 migrations, dependency lockfile, CI gates and default runtime remain unchanged.

## Connection, snapshot and authority

createProviderEvidenceCollector accepts explicit trusted connection/environment/actor/issuer configuration once. Production requires certificate-verified TLS; disposable test configuration requires loopback and crest_migrate_<16hex>. No environment credential lookup, pool, caller SQL/callback/sink, filesystem output, provider action or automatic retry. Existing cleanup/history/review adapters and their4-second READ COMMITTED contracts remain untouched. The collector owns a separate supported pg stream factory and raw socket, closing/destroying it on every success/failure/cancellation without awaiting peer shutdown. No pg private transport property is used in runtime.

A strict guard requires current_user=crest_inventory and a noninheriting, nonprivileged login with exactly one SET-only/nonadmin inventory membership. Reject administrator, combined-capability and cleanup-only connections before the transaction. No runtime service login or grant is provisioned. Disposable integration tests create synthetic logins only after all migration-preflight cases and drop them afterward. These calls expose historical retained evidence only, with no cleanup/application authority.

Start one READ ONLY REPEATABLE READ transaction, then call provider_evidence_export_context as its first data statement. Preserve that original context. Scan all six fixed kinds in declared order using only provider_evidence_export_page, exclusive ascending lower-case UUID cursors and fixed size20. Do not reacquire a pool connection/context per page. Even declared-empty ledgers get a page check; an exactly-full final page gets a terminal page. Require original decimal counts to equal actual observed rows per ledger. Reject missing/extra keys, coercible values, invalid calendar timestamps, mixed actor/issuer/token binding, invalid/duplicate/reversed IDs, unexpected/extra rows, short scans, invalid UTF8/NUL/surrogates, oversized originals and mismatched SHA256. Hash exact original text bytes; never parse/reserialize/repair/filter a source body. No partial result escapes before all six counts match and the transaction's COMMIT is confirmed.

The returned frozen collection/context/counts/array/record objects contain formatVersion1, assurance=snapshot_bytes_only, a new random generation UUID, original context, body-byte count and original record envelopes (kind,recordId,canonicalEvidence,evidenceHash). Empty ledgers are explicit zero counts within that scope, never global absence. snapshotToken is an unkeyed visibility fingerprint, not an authorization/signature, unique transaction ID or physical-database attestation; connection ownership independently enforces consistency. A new explicit call gets a fresh generation and context even if the visibility token happens to repeat. No cross-call/cross-connection resume.

## Resource and failure policy

Fixed conservative private limits:1000 rows across all ledgers and8MiB total original UTF8 body bytes; per-body262144 bytes for inventory observations/8192 otherwise,20-row pages. Validate total declared counts before page reads. Exactly-at-limit collections succeed, any excess fails without truncation. At most one active call per collector instance; simultaneous calls reject before opening another connection. This is not a distributed or per-business export lease. Actual row/body budgets are deliberately smaller than the later complete-export capacity. Oversized scopes require that later bounded streaming/encrypted-parts design, never silently reduced coverage or a larger hidden limit.

Whole invocation deadline30 seconds includes connection/role guard/context/pages/COMMIT. Connect1 second, server statement3 seconds, lock2 seconds, client query3.5 seconds, server idle-in-transaction4 seconds. Owned transport is destroyed on caller abort, deadline, unexpected client end/error or any other failure, aborting an open read-only transaction. Check cancellation/closed state and monotonic elapsed time before/after each SQL call so a late resolution cannot issue more pages after failure. Never wait for rollback/peer acknowledgement on a failed connection. Fixed redacted error exposes no SQL/credentials/host/IDs or raw cause. A failed call returns no partial bytes or generation. The caller must explicitly start a new generation; no automatic retry occurs.

8MiB is a retained original-body budget, not a measured JavaScript heap/process-memory maximum. Strings/metadata/validation buffers/driver overhead and one materialized database page (up to roughly5MiB original bodies) add memory. Fixed trusted PostgreSQL routines and page limits are assumed; no hostile-protocol buffer guarantee or hosted capacity proof is claimed. The total deadline is checked on the event loop and between bounded validations, not a hard real-time CPU preemption guarantee. The30-second budget is below the canonical15-minute full-export ceiling but does not replace future shared capacity, progress and fairness controls.

## Coverage and remaining gates

Scope remains retained_provider_ledgers only: inventory observations, login starts, signed targets, both local finishes, cleanup requests and outcomes for one configured actor/exact issuer, including disabled/old-epoch history. It omits registration-event/cleanup-reference originals, other security/identity/business/configuration ledgers, files, recovery keys and provider-relink material. Valid SHA256/IDs/counts prove source-byte collection under the trusted database functions, not original-body schema validity, foreign graph consistency, independent authenticity/current provider state or restore readiness. Do not call this a complete export or backup. The prior selected-attempt verifier validates a different supported fragment and is not silently promoted into a six-ledger verifier.

No recent-owner-reauth queue/frozen approved export parameters, encrypted private intermediate parts, full manifest/control/attachment inventory, Ready/download endpoint, CSV/XLSX/PDF, durable job/failure record, scheduler/CLI/UI, retention/destruction, restore writer or production activation is implemented. The result stays in the invoking trusted process; future output custody must remain private/encrypted and publish only after its additional complete-export checks. Canonical complete-export/independent-backup/neutral-restore and business-wide concurrency gates remain mandatory. Synthetic only; no spending, signup, provisioning, production apply/deploy or real data. Existing free Node/PostgreSQL tools suffice.
