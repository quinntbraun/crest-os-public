## Atomic capture, replay and findings

The recorder requires READ COMMITTED and typed nonnull request/actor/issuer plus page_size1..100. A nonwaiting transaction advisory lock hashes a domain-separated request UUID: contention returns CREST_INVENTORY_REQUEST_BUSY, never a fabricated result or an instruction to generate a new ID. The adapter must retain that ID, bound its connection/statements/run, and resolve the original outcome. This lock is not actor/business/recovery authority. A theoretical hash collision serializes unrelated work harmlessly. No source/root row lock is explicitly added; ordinary FK integrity locks apply.

An identical committed request returns the original evidence/hash/bytes without rescanning, even if provider state, credentials, local eligibility or actor binding has since changed. Any different actor/issuer/cursor/size under the same UUID conflicts; nothing is overwritten. Before commit, another connection cannot see the row and may see historical lookup NULL while capture is busy. NULL is not proof that a prior transaction cannot still commit. A transaction rollback or insert failure retains no partial receipt and changes no source state. Because capture has no external side effect, a later same-ID capture after a proven rollback is safe. This is scan-request replay, not completed durable tracking of login exchanges, failed attempts, cleanup leases or uncertain provider mutations.

The BEFORE INSERT invoker trigger derives the entire evidence envelope once from the fixed schema18 reader, under UTC/ISO settings. It overwrites supplied timestamps, origin/version, principal, body and hashes, including ordinary privileged INSERTs. It never accepts caller-authored findings or secrets. Snapshot input binding remains the fixed reader's durable actor and exact configured issuer; a future trusted maintenance connection must be matched to that actual provider environment. Supplied issuer text is not cryptographic database identity attestation. Provider users without Crest bindings, old environments and retained local rows whose provider row is absent remain outside this scan.

Classifications are deterministic historical metadata: local_revocation_review when the sample has a local revocation; otherwise unregistered_review for no registration; otherwise registered_review for sampled actor-disabled/epoch mismatch/local expiry/provider expiry or non-AAL2 evidence; otherwise registered_observed. All original safe fields remain. These labels never authorize provider deletion, certify a failed logout, prove an orphan or establish application eligibility. Membership, idle lifetime, current credentials, fresh SDK/provider/local checks and request authorization are not replaced. No row is automatically resolved after a later observation or provider disappearance; cleanup references remain review_required.

Each bounded page is one reader snapshot. observedAt/row observed_at mean the database statement's start time; recordedAt is the later server recording time. Neither is a fresh post-wait authentication assertion. Pages are not a cross-page consistent snapshot. Inserts behind a cursor may require a new sweep; an empty or final page is not absence/completion proof. Historical lookup scopes exact request/actor/issuer, works read-only without querying current provider state, and returns NULL for absent/mismatched records. No side effect, cursor advance, current binding upgrade or cleanup permission comes from lookup/replay.
